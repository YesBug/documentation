请求失败时，先查看 HTTP 状态码，再结合响应中的错误详情定位问题。不同模型和上游服务的错误结构可能不同，不要只依赖单一的错误字符串。

## 先确定失败发生在哪一层

| 观察到的现象 | 先处理哪里 | 下一步 |
| --- | --- | --- |
| 程序提示环境变量不存在、找不到模块 | 应用启动与依赖 | 检查启动进程是否加载密钥、包是否装在当前运行环境 |
| 连接失败，没有 HTTP 状态 | 网络、DNS、代理或 TLS | 从应用运行的同一环境发起模型列表请求 |
| 收到非 2xx HTTP 状态 | 鉴权、请求、权限或服务端处理 | 保留状态和错误体，按下表定位 |
| HTTP 成功，但 JSON 解析失败 | 响应读取方式 | 检查是否收到 SSE、纯文本、音频或 HTML 页面 |
| HTTP 成功，结果仍是排队中 | 异步任务流程 | 保存任务 ID 并查询，不要把提交成功当成生成完成 |
| 返回正常文字，但不符合预期 | 模型输入与业务校验 | 检查消息历史、提示词、结束原因与结果校验 |

如果 cURL 能调用而 SDK 不能，优先对比两者的最终 URL、模型 ID、实际请求字段和运行环境。SDK 抛出的异常名称描述客户端看到的结果，不一定等于平台返回的业务错误码。

## 保留一次可诊断的响应

以下命令只查询模型列表，将响应头与响应体分开保存，并输出 HTTP 状态。10 秒连接超时和 30 秒总超时是排查示例值，不是 MaxAPI 的服务时限。

```bash 保存诊断文件
curl --silent --show-error \
  --connect-timeout 10 \
  --max-time 30 \
  --dump-header diagnostic-headers.txt \
  --output diagnostic-body.txt \
  --write-out 'HTTP %{http_code}\n' \
  https://api.maxapi.ai/v1/models \
  -H "Authorization: Bearer $MAXAPI_API_KEY"
```

- 有真实 HTTP 状态时，先读取 `diagnostic-body.txt` 中的错误详情。它未必是 JSON。
- 显示 `HTTP 000` 并伴随 cURL 连接错误时，没有收到可用的 HTTP 响应，先处理网络层。
- 该命令没有使用 `--fail`，所以 HTTP `401` 等错误仍可能以正常的命令退出状态结束；以输出的 HTTP 状态为准。
- 分享文件前检查响应头、错误体是否包含账户信息、个人数据或敏感输入。不要改用会直接展示鉴权头的日志来收集公开排查材料。

## 常见 HTTP 状态

下面按通用 HTTP 语义提供排查方向，并非所有 MaxAPI 模型的完整错误码规范。具体原因以实际响应为准。

| 状态码 | 常见排查方向 | 建议操作 |
| --- | --- | --- |
| `400` | 请求体、字段类型或模型参数不匹配 | 检查 JSON 格式，减少为最小请求后逐项添加参数 |
| `401` | 密钥缺失、无效或验证头不正确 | 检查环境变量、Bearer 格式与密钥状态 |
| `403` | 当前请求没有所需访问权限 | 核实账户和目标模型的访问条件 |
| `404` | 路径或资源不存在 | 检查 Base URL、端点与模型 ID |
| `429` | 请求频率、配额或其他用量限制 | 阅读错误详情，检查账户状态，降低并发并按需退避重试 |
| `5xx` | 服务处理或上游调用失败 | 记录响应，使用有限次数的退避重试，并检查持续失败情况 |

## 用最小请求定位问题

首先调用模型列表，确认网络连通性和验证配置：

```bash
curl --fail-with-body https://api.maxapi.ai/v1/models \
  -H "Authorization: Bearer $MAXAPI_API_KEY"
```

随后按照 [快速开始](/zh/quickstart) 发送只包含 `model` 和 `messages` 的对话请求。如果最小请求成功，再逐项恢复原来的参数、长输入和流式配置。

## 检查接口地址

SDK 的 Base URL 和原始 HTTP 的完整端点用途不同：

| 场景 | 正确地址 |
| --- | --- |
| OpenAI SDK 的 Base URL | `https://api.maxapi.ai/v1` |
| 原始 HTTP 创建对话 | `https://api.maxapi.ai/v1/chat/completions` |
| 原始 HTTP 查询模型 | `https://api.maxapi.ai/v1/models` |

确认最终请求路径没有重复的 `/v1`，也没有将官网或控制台域名当作 API 地址。

## 超时与连接失败

如果没有收到 HTTP 响应，请检查本地网络、DNS、代理配置，以及服务端能否访问 API 域名。长文本生成可能需要更长时间，应根据应用场景合理配置超时。

流式请求还需要检查反向代理是否缓冲响应、连接是否被中间层提前关闭。具体说明见 [流式响应](/zh/guides/streaming)。

## 设计合理的重试

网络中断、部分 `429` 或 `5xx` 错误可能适合重试，但无效密钥、错误模型 ID 和不支持的参数通常需要先修正配置。

重试时采用逐步增加等待时间并加入随机抖动的策略，设置最大次数；响应提供 `Retry-After` 时可参考该值。先检查 SDK 自身的重试设置，避免重复叠加。

超时并不代表服务端未处理请求。重发请求可能造成重复生成或额外用量，需要按业务场景权衡。

## 收集排查信息

通过 [控制台](https://platform.maxapi.ai) 提供的支持入口反馈问题时，附上发生时间与时区、接口路径、模型 ID、HTTP 状态码和已脱敏的错误响应。如果响应中提供请求标识，也一并保留。

删除 API Key、个人信息与业务敏感内容后再分享日志。不要提交完整的 `Authorization` 请求头。

## HTTP 200 但没有生成结果

部分任务接口在 HTTP 成功响应中另外提供业务 `code`、`status` 或错误对象。应同时检查业务结果：

- Midjourney 提交返回 `result` 任务 ID，不等于图片已完成。
- Suno v2 的外层生成状态与每首歌曲的状态不同，要继续检查 `clips`。
- 视频任务返回排队或处理中状态时，应调用对应查询接口。
- 某些原生接口会把错误放在 `base_resp` 或其他协议字段中，不能一律读取 `choices`。

具体流程见 [异步任务与回调](/zh/guides/async-tasks)。

## 视频查询 404 或任务一直未完成

核对任务 ID 是从哪种协议返回的，并使用同一协议的查询端点。不要将 `clips[].id`、`operation.name`、`data.task_id` 混用；也不要复制资料中固定的示例任务 ID。

保留原始状态与错误信息，对未知状态设置总超时。生成任务已经失败时，先排查输入素材、模型权限和返回原因，不要通过不断提交新任务来“查询”。

## 上传或下载格式不正确

文件上传使用 `multipart/form-data`，由 HTTP 客户端自动生成 boundary。图片 URL 应能被处理任务的服务端读取；本地路径仅适用于客户端上传，不能直接当作远程 URL。

语音生成和文件下载可能返回二进制数据。若出现 JSON 解析错误，请先检查响应的 `Content-Type`、HTTP 状态以及接口的返回格式；不要把错误 JSON 当成有效音频保存。

## 根据请求类型缩小问题范围

<Tabs>
<Tab title="聊天与流式">

先使用一条短 `user` 消息，关闭流式，仅保留 `model` 和 `messages`。普通请求成功后再启用 `stream`。如果流式原始事件持续到达而页面不更新，检查应用输出缓冲；如果连接中途断开，检查客户端、网关与应用各自的超时。

`content` 为空时先检查工具调用；文本被截断时检查 `finish_reason`。不要仅凭一个 SDK 属性为空就认定整个请求失败。

</Tab>
<Tab title="文件上传">

从一个已知能正常打开的短音频或小图片开始。确认文件在应用运行环境中真实存在，以二进制方式打开；cURL 使用 `@` 上传内容。让客户端设置 multipart boundary，删除手写的 JSON Content-Type。

如果短文件成功而原文件失败，再比较真实编码、尺寸、时长与模型限制。改变扩展名不会改变文件编码。

</Tab>
<Tab title="视频与音乐任务">

区分提交请求、查询请求和结果下载。提交成功后保存 ID，不要重复提交来查看进度；查询失败优先检查 ID 来源和查询协议；结果下载失败优先重试已有结果 URL，而不是马上重新生成。

达到应用等待期限时，将状态记录为“待确认”，不要直接认定生成失败。后续可继续查询，具体字段见 [异步任务](/zh/guides/async-tasks)。

</Tab>
</Tabs>

## 准备支持请求

使用能复现问题的最小输入，不要提交真实密钥。下面是一份可以直接填写的模板；请求标识仅在接口实际返回时提供，不要自行猜测其请求头名称。

```text 支持请求模板
发生时间与时区：YYYY-MM-DD HH:mm:ss Asia/Shanghai
运行环境：本地 / 云服务器；语言与 SDK 版本
请求方法和路径：POST /v1/chat/completions
模型 ID：填写实际模型 ID
HTTP 状态：填写实际状态；没有响应时写“未收到”
请求或任务标识：如有则填写
问题频率：每次发生 / 偶发；最近一次成功时间
最小复现：仅保留必要字段和可公开的输入
预期结果：
实际结果：脱敏后的错误内容或状态
已尝试：模型列表是否成功、最小请求是否成功
```

确认脱敏后，通过 [控制台](https://platform.maxapi.ai) 提供的支持入口提交。如果密钥曾经进入公开代码、截图或日志，应先在控制台处理该密钥，再分享已经脱敏的复现信息。
