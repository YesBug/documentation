MaxAPI 的常用接口页面提供 Mintlify 原生在线调试面板。你可以查看请求方法与路径，填写鉴权和参数，再检查实际返回的状态、响应体或媒体内容。

## 发送第一次请求

<Steps>
  <Step title="打开模型列表">
    前往 [模型列表](/zh/api-reference/models)，选择接口页面中的 **Try it**（在线调试）入口。该接口无需请求体，适合先核对密钥与连接。
  </Step>
  <Step title="填写 API Key">
    从 [控制台](https://platform.maxapi.ai) 获取密钥，在调试面板的 Bearer 鉴权字段填写密钥值。生成的请求头应为 `Authorization: Bearer 你的密钥`，不要重复添加 `Bearer`。
  </Step>
  <Step title="检查请求并发送">
    确认目标地址为 `https://api.maxapi.ai/v1/models`，然后发送请求。成功时，从响应的 `data[].id` 选取适合任务的模型 ID。
  </Step>
  <Step title="尝试对话接口">
    打开 [创建对话](/zh/api-reference/chat-completions)，填写支持对话的模型 ID 和 `messages`。先验证最小请求，再逐项增加可选参数。
  </Step>
</Steps>

<Note>
在线调试会发送真实请求，生成操作可能产生实际用量。不要在共享设备上留下密钥；分享截图和响应前，移除鉴权信息与敏感内容。
</Note>

## JSON、文件与流式输出

| 请求类型 | 调试方式 |
| --- | --- |
| JSON | 在 **Form** 与 **JSON** 视图间切换；发送前确认 JSON 有效 |
| 文件上传 | 在文件字段选择本地文件，适用于 [图像编辑](/zh/api-reference/images-edits) 与 [音频转录](/zh/api-reference/audio-transcriptions)；由客户端生成 multipart boundary |
| SSE | 在支持流式的模型上设置 `stream: true`，响应按文本逐段显示；可点击 **Stop** 停止读取 |
| 音频 | [文本转语音](/zh/api-reference/audio-speech) 返回受支持的音频内容类型时，使用响应中的播放器查看结果 |

调试请求通过文档平台的代理转发。代码示例仍使用 MaxAPI 的正式接口地址；将示例接入应用时，请按 [身份验证](/zh/authentication) 在服务端管理密钥。

## 请求失败时

先检查 HTTP 状态与响应内容。`401` 优先核对密钥，参数错误先减少为最小请求，模型或路由错误则核对账户权限和 Base URL。完整步骤见 [错误排查](/zh/help/errors)。

如果需要排查长时间流式连接，使用 [流式响应指南](/zh/guides/streaming) 中的 SDK 或 cURL 示例，对照确认网络、超时及响应缓冲情况。

## 使用最小 JSON 验证对话

在 [创建对话](/zh/api-reference/chat-completions) 的 JSON 视图中使用下面的请求。将 `YOUR_MODEL_ID` 换为当前账户支持聊天的实际模型 ID，API Key 仍填写在鉴权区域，不要放进 JSON。

```json 最小对话请求
{
  "model": "YOUR_MODEL_ID",
  "messages": [{"role": "user", "content": "请用一句话介绍 API 的作用。"}]
}
```

依次确认三个结果：HTTP 请求成功、`choices` 中存在回复、`finish_reason` 符合预期。成功后再启用 `stream`、更换长输入或增加工具定义，每次只改变一个因素。

## 从调试面板迁移到代码

| 在线调试中确认的配置 | 应用代码中的对应项 |
| --- | --- |
| Bearer 鉴权字段 | 服务端环境变量和 Authorization 请求头，或 SDK 的 `api_key` |
| 完整请求地址 | HTTP 完整端点；SDK 使用 `https://api.maxapi.ai/v1` |
| JSON 中的模型 ID | 配置项 `MAXAPI_MODEL` 或相应任务的模型变量 |
| JSON 表单 | 应用构造的对象，不需要复制表单显示标签 |
| 本地上传文件 | 应用运行环境中真实存在的文件字节 |
| 流式响应区域 | SDK 流迭代或按事件解析 SSE 的代码 |

复制代码后，检查其中是否仍有占位符、是否带入了真实密钥，以及示例使用的模型是否正确。调试成功后可继续阅读 [Python](/zh/guides/python)、[Node.js](/zh/guides/nodejs) 或相应接口页的保存结果示例。

## 对比浏览器与应用的差异

| 现象 | 接下来检查 |
| --- | --- |
| 面板成功，应用失败 | 两边的最终地址、环境变量、模型 ID、请求字段和上传文件是否一致 |
| 应用成功，面板失败 | 重新检查鉴权字段、必需参数和文档代理链路；保留面板实际错误 |
| 流式面板有文字，应用没有 | 检查应用是否按增量读取，以及中间层是否缓冲 |
| 点击停止后仍有用量 | 停止读取不代表上游一定取消，结合控制台记录核对 |
| 音频或图片没有正确展示 | 检查状态和 Content-Type，使用接口页的文件保存示例验证原始结果 |

面板用于验证请求结构与响应。并发、超时、自动重试、任务恢复和业务结果校验，需要在你的应用中实现。不要通过反复点击生成来查询异步任务状态。
