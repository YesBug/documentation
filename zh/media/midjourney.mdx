MaxAPI 的 Midjourney 接口采用异步任务流程：**提交提示词 → 得到任务 ID → 查询完成结果 → 选择图片动作**。它不使用 Chat Completions，也不在请求体里填写聊天模型的 `model`。

## 先找到你要做的事

| 你想做什么 | 使用的接口 | 接下来做什么 |
| --- | --- | --- |
| 文字生成图片，或参考图片加文字 | [Imagine](/zh/api-reference/midjourney/imagine) | 查询任务，读取图片和按钮 |
| 混合多张图片 | [Blend](/zh/api-reference/midjourney/blend) | 查询生成结果 |
| 从图片提取提示词 | [Describe](/zh/api-reference/midjourney/describe) | 读取描述，再选提示词生成图片 |
| 分析、精简提示词 | [Shorten](/zh/api-reference/midjourney/shorten) | 读取分析结果，再选择生成 |
| 选择单张图、变化、重新生成、缩放或平移 | [Action](/zh/api-reference/midjourney/action) | 根据返回结果继续查询，或进入 Modal |
| 修改提示词、局部重绘、确认交互 | [Modal](/zh/api-reference/midjourney/modal) | 提交交互参数后，查询最终任务 |

图片输入的完整示例见 [参考图、混图与反推](/zh/media/midjourney/inputs)；U/V、Remix 和局部重绘见 [后续动作](/zh/media/midjourney/actions)。

## 准备配置

在 [控制台](https://platform.maxapi.ai) 获取可调用 Midjourney 的密钥。下面的终端示例使用 Bash、`curl`、Python 3 和 `jq`。

```bash
export MAXAPI_API_KEY="替换为你的 MaxAPI API Key"
export MAXAPI_MJ_BASE_URL="https://api.maxapi.ai/mj"
```

| 模式 | Base URL |
| --- | --- |
| Fast | `https://api.maxapi.ai/mj` |
| Turbo | `https://api.maxapi.ai/mj-turbo/mj` |
| Relax | `https://api.maxapi.ai/mj-relax/mj` |

选择你账户可用的模式，并在提交、查询和后续动作中保持一致。**这些地址不加 `/v1`**。不同模式的价格、配额与可用性以账户配置为准。

## 1. 提交绘图

下面的提示词生成一张用于产品展示的陶瓷杯图片。`botType` 选择 `MID_JOURNEY`；使用 Niji 时，对应值为 `NIJI_JOURNEY`。

```bash
curl --fail-with-body "$MAXAPI_MJ_BASE_URL/submit/imagine" \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
    "botType": "MID_JOURNEY",
    "prompt": "A handmade ceramic cup on a clean studio background, soft side lighting, product photography",
    "state": "product-photo-001"
  }' \
  --output mj-submit.json
```

成功提交后的结构如下。这里的 `TASK_A` 是说明用的占位符：

```json
{
  "code": 1,
  "description": "提交成功",
  "result": "TASK_A"
}
```

`code: 1` 表示提交成功，`code: 22` 表示已进入队列；二者都不代表图片已经生成。`result` 是需要保存的任务 ID，HTTP `200` 本身不能证明业务成功。

命令成功后，提取自己的任务 ID。Python 会保留 JSON 整数的精度，再将 ID 转成字符串：

```bash
TASK_ID="$(python3 - <<'PY'
import json
from pathlib import Path

result = json.loads(Path("mj-submit.json").read_text(encoding="utf-8"))
if result.get("code") not in (1, 22):
    raise SystemExit(result.get("description", "Submission was not accepted"))
task_id = result.get("result")
if isinstance(task_id, bool) or not isinstance(task_id, (str, int)) or str(task_id) == "":
    raise SystemExit("No valid task ID in result")
print(str(task_id))
PY
)"
: "${TASK_ID:?请先检查 mj-submit.json 中的业务结果}"
export TASK_ID
```

## 2. 查询到任务完成

```bash
TASK_ID_ESCAPED="$(python3 -c 'import os, urllib.parse; print(urllib.parse.quote(os.environ["TASK_ID"], safe=""))')"
curl --fail-with-body "$MAXAPI_MJ_BASE_URL/task/$TASK_ID_ESCAPED/fetch" \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  --output mj-task.json

jq '{id, status, progress, imageUrl, failReason}' mj-task.json
```

查询过程中可能看到 `NOT_START`、`SUBMITTED` 或 `IN_PROGRESS`。稍后再次查询**同一个任务**，不要重新提交 `imagine`。可运行的自动轮询脚本见 [任务状态与回调](/zh/media/midjourney/tasks)。

成功任务示意：

```json
{
  "id": "TASK_A",
  "action": "IMAGINE",
  "status": "SUCCESS",
  "progress": "100%",
  "imageUrl": "https://example.com/generated-grid.png",
  "buttons": [
    {"label": "U1", "customId": "COPY_THE_ACTUAL_CUSTOM_ID_FROM_THIS_TASK"}
  ]
}
```

以 `status: "SUCCESS"` 判断成功，再读取 `imageUrl`。生成过程中也可能出现预览图片地址，因此不能只检查 URL 是否存在。`FAILURE` 时读取 `failReason`；`CANCEL` 表示已取消。

## 3. 看懂图片和按钮

普通绘图结果可能是四宫格。`buttons` 告诉你这一次结果可执行哪些操作：`label` 是展示给人的名称，`customId` 才是提交给 API 的动作标识。

```bash
jq -r '.buttons[]? | [.label, .emoji, .customId] | @tsv' mj-task.json
```

例如，想选择第一张图时，在当前任务返回的按钮中寻找 `U1`，将它的完整 `customId` 与任务的 `id` 一起提交给 Action。不要把字符串 `"U1"` 直接填进 `customId`，也不要从别的任务复制动作标识。

| 标识 | 从哪里取得 | 用在哪里 |
| --- | --- | --- |
| 原任务 ID | Imagine 返回的 `result`，或查询结果的 `id` | Action 请求的 `taskId` |
| 动作标识 | 当前任务的 `buttons[].customId` | Action 请求的 `customId` |
| 后续任务 ID | Action 或 Modal 返回的 `result` | 后续的任务查询；不要继续查询原任务 |

## 最容易接错的地方

| 现象 | 正确处理 |
| --- | --- |
| 返回任务 ID，却没有图片 | 提交和查询是两个请求，继续查询直到成功 |
| 放大后仍显示原图 | 保存 Action 返回的任务 ID，查询后续任务 |
| 动作返回 `code: 21` 且提示等待输入，或任务状态为 `MODAL` | 这是需要交互确认的动作分支，按 [Modal 流程](/zh/media/midjourney/actions) 补充输入 |
| 查询不到任务 | 检查密钥、完整 ID 和模式前缀是否与提交一致 |
| 用 JavaScript 保存 ID 后对不上 | 保持 ID 为字符串，不要转换为 `Number`；过长数值 ID 应用无损 JSON 解析处理 |

`state` 是你自己的业务关联值，例如订单或生成记录编号。它不是任务 ID，也不能代替 `taskId`。
