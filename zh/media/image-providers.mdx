图像生成既有 [OpenAI 兼容 Images 格式](/zh/api-reference/images)，也有厂商专用格式和异步任务格式。选择前先确认当前模型开通的路由；相同的生成目标不意味着请求体可以通用。

## 选择请求格式

| 格式 | 常见入口 | 请求编码 | 结果读取方式 |
| --- | --- | --- | --- |
| OpenAI Images | `/v1/images/generations`、`/v1/images/edits` | JSON 或 multipart | 图像 URL 或 Base64 |
| Gemini 原生图像 | `/v1beta/models/{model}:generateContent` | JSON `contents[].parts[]` | 从模型返回的内容块中读取 |
| Stable Diffusion 3 | `/sd/v2beta/stable-image/generate/sd3` | multipart | 依据 `Accept` 读取图片或 JSON |
| Ideogram | `/ideogram/generate` | JSON `image_request` | `data[]` 中的图像信息 |
| 异步图像兼容格式 | `/v1/videos` | 该图像分支使用 multipart | 先查询任务，再下载内容 |

下面各节仅适用于已开通对应格式的渠道。专用协议通常使用普通 HTTP 客户端；OpenAI SDK 不会自动把 `prompt` 转换为 Gemini 的内容块或 Ideogram 的 `image_request`。

## Gemini：generateContent

接口资料给出了 `gemini-2.5-flash-image` 的 `generateContent` 路由。使用其他模型 ID 前，需先确认该模型也开放同一协议。

```http 资料中的图像路由
POST https://api.maxapi.ai/v1beta/models/gemini-2.5-flash-image:generateContent
```

| 字段 | 作用 |
| --- | --- |
| `contents[].role` | 消息角色，例如 `user` |
| `contents[].parts[].text` | 图像描述或编辑指令 |
| `contents[].parts[].inline_data` | 参考图内容块，使用时提供 `mime_type` 和 Base64 `data` |
| `generationConfig.responseModalities` | 此图像协议示例使用 `TEXT` 与 `IMAGE` |

将 `MAXAPI_GEMINI_IMAGE_MODEL` 设置为当前已确认可用的模型 ID。下面以文本输入演示相同的内容块结构：

```bash Gemini 图像请求
: "${MAXAPI_GEMINI_IMAGE_MODEL:?请设置支持 generateContent 图像生成的模型 ID}"
MODEL_ESCAPED="$(printf '%s' "$MAXAPI_GEMINI_IMAGE_MODEL" | jq -sRr @uri)"
jq -n '{
  contents: [{
    role: "user",
    parts: [{text: "Create a watercolor illustration of a small library beside a river."}]
  }],
  generationConfig: {responseModalities: ["TEXT", "IMAGE"]}
}' | curl --fail-with-body \
  "https://api.maxapi.ai/v1beta/models/$MODEL_ESCAPED:generateContent" \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @- \
  --output gemini-image.json
```

编辑参考图时，在同一条消息的 `parts` 中添加图像内容块，保留其真实 MIME 类型。不要把整个 `data:image/...;base64,...` URL 当作纯 Base64 数据直接塞入 `data`。

此格式的结果是多模态内容，可能同时含文本和图片，也可能因输入或模型限制未返回图片。遍历返回的候选内容块，按实际类型读取；不要套用 OpenAI Images 的 `data[0].url` 解析逻辑。MaxAPI 此路由使用 Bearer 鉴权，示例中不要混入厂商直连域名或直连密钥。

### 用本地参考图构造编辑请求

在支持图像编辑的渠道中，把真实图片编码后放入 `inline_data.data`。下面示例读取 JPEG 或 PNG 文件；文件扩展名应与实际格式一致。它只生成请求体，不消耗生成额度。

```python build_gemini_edit.py
import base64
import json
import mimetypes
import sys
from pathlib import Path


if len(sys.argv) != 2:
    raise SystemExit("Usage: python build_gemini_edit.py IMAGE_FILE")
image = Path(sys.argv[1])
mime_type = mimetypes.guess_type(image.name)[0]
if mime_type not in {"image/jpeg", "image/png"}:
    raise ValueError("This example accepts a JPEG or PNG file with a matching extension")
payload = {
    "contents": [{
        "role": "user",
        "parts": [
            {"text": "Keep the main subject unchanged and replace the background with a quiet garden."},
            {"inline_data": {
                "mime_type": mime_type,
                "data": base64.b64encode(image.read_bytes()).decode("ascii"),
            }},
        ],
    }],
    "generationConfig": {"responseModalities": ["TEXT", "IMAGE"]},
}
Path("gemini-edit-request.json").write_text(json.dumps(payload), encoding="utf-8")
print("Request body saved to gemini-edit-request.json")
```

```bash 构造并发送图像编辑请求
python build_gemini_edit.py ./reference.png
: "${MAXAPI_GEMINI_IMAGE_MODEL:?请设置已开通的图像编辑模型 ID}"
MODEL_ESCAPED="$(printf '%s' "$MAXAPI_GEMINI_IMAGE_MODEL" | jq -sRr @uri)"
curl --fail-with-body \
  "https://api.maxapi.ai/v1beta/models/$MODEL_ESCAPED:generateContent" \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @gemini-edit-request.json \
  --output gemini-edit-response.json
```

保留 `gemini-edit-response.json` 检查实际输出结构。此路由的现有资料未完整定义响应 schema，因此不要把“HTTP 200”直接显示为“图片已生成”：先确认候选内容确实有图片块，再按返回的 MIME 类型解码保存。未返回图片时，读取文本或错误信息，检查模型是否支持图像输出及当前输入。

## Stable Diffusion 3：multipart 与 Accept

SD3 接口通过 `mode` 区分文生图和图生图。模型、输出尺寸以及参数组合以当前 SD 渠道支持情况为准。

```http Endpoint
POST https://api.maxapi.ai/sd/v2beta/stable-image/generate/sd3
```

| 字段 | 类型 | 使用条件 |
| --- | --- | --- |
| `prompt` | `string` | 必填，图像描述 |
| `model` | `string` | 选择已开通的 SD3 模型 |
| `mode` | `string` | `text-to-image` 或 `image-to-image` |
| `image` | 文件 | 图生图模式使用 |
| `strength` | `number` | 图生图模式使用，控制参考图影响程度 |
| `aspect_ratio` | `string` | 文生图支持时指定比例 |
| `output_format` | `string` | 选择支持的图片格式 |

`Accept: image/*` 请求图片内容，`Accept: application/json` 请求包含 Base64 的 JSON。上传表单时不手写 `Content-Type`，由 cURL 生成带 boundary 的请求头。

```bash SD3 文生图，保存图片
: "${MAXAPI_SD_MODEL:?请设置已开通的 SD3 模型 ID}"
curl --fail-with-body https://api.maxapi.ai/sd/v2beta/stable-image/generate/sd3 \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Accept: image/*" \
  --form-string "model=$MAXAPI_SD_MODEL" \
  --form-string "mode=text-to-image" \
  --form-string "prompt=A small wooden cabin beside a quiet lake, ink illustration" \
  --form-string "output_format=png" \
  --dump-header sd-image.headers \
  --output sd-image.png
```

检查 HTTP 状态和 `Content-Type` 后再把文件作为图片展示；出错响应仍可能是 JSON。图生图需添加文件上传与 `strength`，不能只改变 `mode`。

SDXL 的 `/sd/v1/generation/{engine_id}/text-to-image` 是另一套字段结构，不应复用 SD3 的 multipart 参数。更多分支见 [接口目录](/zh/api-reference/catalog)。

### SD3 图生图

在支持 `image-to-image` 的模型上，提供文件和已确认有效的 `strength`。先把 `MAXAPI_SD_STRENGTH` 设置为该渠道接受的数值；不要把其他模型的强度参数范围当作这里的约束。

```bash 上传参考图并保存生成结果
: "${MAXAPI_SD_MODEL:?请设置已开通的 SD3 模型 ID}"
: "${MAXAPI_SD_STRENGTH:?请设置该模型接受的 strength 数值}"
curl --fail-with-body https://api.maxapi.ai/sd/v2beta/stable-image/generate/sd3 \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Accept: image/*" \
  --form-string "model=$MAXAPI_SD_MODEL" \
  --form-string "mode=image-to-image" \
  --form-string "prompt=Keep the building layout and redraw the scene as a watercolor illustration" \
  --form "image=@./reference.png" \
  --form-string "strength=$MAXAPI_SD_STRENGTH" \
  --form-string "output_format=png" \
  --dump-header sd-edit.headers \
  --output sd-edit.download
```

如果返回参数错误，检查上传的 `image` 是否为文件内容、`strength` 是否有效，以及所选模型是否支持图生图。保存成 `.download` 是为了先检查响应类型，避免把 JSON 错误内容误认为 PNG。

## Ideogram：image_request 包装层

Ideogram 生成接口使用 JSON 对象 `image_request`。图像混合、放大和描述操作可能改用 multipart，需分别确认请求编码。

```http Endpoints
POST https://api.maxapi.ai/ideogram/generate
POST https://api.maxapi.ai/ideogram/remix
POST https://api.maxapi.ai/ideogram/upscale
POST https://api.maxapi.ai/ideogram/describe
```

| 字段 | 说明 |
| --- | --- |
| `image_request.prompt` | 必填的图像描述 |
| `image_request.model` | 当前渠道支持的 Ideogram 模型值 |
| `image_request.aspect_ratio` | 此协议的比例标识，格式与普通 `16:9` 参数不同 |
| `image_request.resolution` | 指定分辨率时使用；不能与 `aspect_ratio` 同时传入 |
| `image_request.magic_prompt_option` | 支持时控制提示词增强 |
| `image_request.style_type` | 支持该风格参数的模型使用 |

```bash Ideogram 文生图
: "${MAXAPI_IDEOGRAM_MODEL:?请设置已开通的 Ideogram 模型值}"
jq -n --arg model "$MAXAPI_IDEOGRAM_MODEL" '{
  image_request: {
    model: $model,
    prompt: "A minimal poster for a reading club, warm colors, the title READ TOGETHER"
  }
}' | curl --fail-with-body https://api.maxapi.ai/ideogram/generate \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @- \
  --output ideogram-images.json
```

成功响应使用 `data[]`，可包含 `url`、`prompt`、`resolution` 和 `is_image_safe`。`url` 可能为空，需要逐项检查；不要默认每个数组元素都有可下载图片。取得结果后及时保存到自己的存储，不把生成链接的保存时长写死在业务逻辑中。

### 读取并保存 Ideogram 图片

保留整个 `data[]`，不要只保存第一张图的 URL：其中的提示词、分辨率和安全标记有助于应用展示和排错。下面选择第一张有 HTTPS 地址、且没有明确标记为不安全的图片：

```bash 提取一张可用图片并下载
IMAGE_URL="$(jq -er '
  [.data[]? |
    select(.is_image_safe != false) |
    select(.url | type == "string") |
    select(.url | startswith("https://"))
  ][0].url // empty
' ideogram-images.json)"
: "${IMAGE_URL:?没有可用图片，请检查 data 和错误信息}"
curl --fail --location --proto '=https' --proto-redir '=https' \
  --connect-timeout 10 --max-time 120 \
  --dump-header ideogram-image.headers \
  --output ideogram-image.download "$IMAGE_URL"
```

检查下载响应的 `Content-Type`，确认是图片后按实际格式命名。生成请求和图片下载是两次独立请求：只有前者向 MaxAPI 发送 Bearer 密钥，下载链接使用其自身的访问方式。

## 异步图像：复用 videos 任务资源

部分图像渠道通过兼容任务资源提交与查询图片。虽然路径叫 `/v1/videos`，该分支的返回对象可以是 `image`，生成内容仍是图片。

| 步骤 | 方法和路径 | 作用 |
| --- | --- | --- |
| 提交 | `POST /v1/videos` | multipart 图像任务；示例包含 `model`、`prompt` 和可选 `input_reference` 文件 |
| 查询 | `GET /v1/videos/{video_id}` | 使用提交返回的 `id` 查询 |
| 下载 | `GET /v1/videos/{task_id}/content` | 获取完成后的图像内容 |

这个路径同时出现在视频、角色和图像兼容流程中。接口汇总中同一路径可能只保留某一分支的示例，不能把角色创建字段当作图像生成参数。接入前需确认具体模型和图像任务分支，因此本节不提供混合多个分支的通用请求体。

保存响应中的 `id`，根据该分支的状态判断任务完成，再读取内容。示例中 `status: "in_progress"` 表示处理中；不要借用统一视频接口的大写 `SUCCESS` 去判断所有 `/v1/videos` 任务。下载时检查真实 `Content-Type`，不要把二进制图片当作 JSON 解析。

任务保存、有限轮询和下载处理建议见 [异步任务与回调](/zh/guides/async-tasks)。


## 按输出类型排查

| 现象 | 处理方式 |
| --- | --- |
| SDK 报未知参数或无法解析响应 | 确认是否在用 OpenAI SDK 调厂商专用协议；必要时改用普通 HTTP |
| Gemini 返回文字，没有图片 | 检查模型的图像输出能力、`responseModalities` 和实际内容块 |
| SD3 结果打不开 | 先检查 HTTP 状态和 `Content-Type`，避免把 JSON 错误保存成图片 |
| Ideogram 的 `data[]` 存在但 URL 为空 | 检查每个元素与安全标记，不要盲目读取第一项 |
| 参考图被拒绝 | 核对 MIME 类型、编码方式、文件内容，以及模型的输入约束 |
| `/v1/videos` 图像任务一直未完成 | 使用该图像分支的状态规则，检查任务 ID 与结果下载步骤 |
