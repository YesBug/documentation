Embeddings 将文本编码为数值向量。可以先为文档片段生成向量并建立索引，再为查询生成向量，检索相关内容用于后续对话。

单条文本长度、批量条数和输出维数由模型决定。提交前去除空文本，按语义拆分长文档，并保留每个片段的来源与位置。

## 读取批量结果

使用 `data[].index` 将结果映射回输入。浮点格式的向量位于 `data[].embedding`；若主动请求 Base64 格式，应按对应编码处理。

## 用于知识库

1. 将文档切分为适合检索的片段，保存原文、来源和向量。
2. 使用相同模型与维数生成用户问题的向量。
3. 在向量数据库中检索相关片段。
4. 将检索到的原文加入 [对话请求](/zh/api-reference/chat-completions)，让模型基于这些内容回答。

更换嵌入模型或维数时，应重新生成对应索引。即使向量长度相同，不同模型的向量也不应直接混用。

## 常见问题

空输入、单条文本过长、批次过大或不支持的 `dimensions` 都可能引发参数错误。先用一条短文本和最小参数验证，再恢复批量处理；遇到限流时降低批次与并发，详见 [错误排查](/zh/help/errors)。
