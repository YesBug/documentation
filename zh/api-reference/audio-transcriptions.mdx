音频转录接口接收音频文件，输出原语言文本。需要英文翻译时，请使用 [音频翻译](/zh/api-reference/audio-translations)。模型和文件限制取决于账户启用的通道。

请求体使用 `multipart/form-data`。使用 cURL 的 `-F` 时，让客户端自动生成 boundary，不要手写缺少 boundary 的 Content-Type。

使用前确认所选模型的文件格式、大小和音频时长限制；文件扩展名必须与实际编码相符。

## 转录音频

将音频保存为 `meeting.mp3`，准备密钥，并将 `MAXAPI_AUDIO_MODEL` 设为支持转录的模型。

<Tabs>
<Tab title="cURL">

```bash cURL：转录
curl --fail-with-body https://api.maxapi.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -F "model=$MAXAPI_AUDIO_MODEL" \
  -F "file=@meeting.mp3" \
  -F "response_format=json"
```

</Tab>
<Tab title="Python">

安装 `openai` 包后，也可以用二进制方式打开文件并传给 Python SDK：

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["MAXAPI_API_KEY"],
    base_url="https://api.maxapi.ai/v1",
)
with open("meeting.mp3", "rb") as audio:
    result = client.audio.transcriptions.create(
        model=os.environ["MAXAPI_AUDIO_MODEL"],
        file=audio,
        response_format="json",
    )
print(result.text)
```

</Tab>
</Tabs>

JSON 格式的转录文本位于 `text`。如果输出为空，检查音轨是否有效、是否存在语音，以及录音质量和语言设置。

## 字幕与时间信息

支持字幕的模型可使用 `response_format=srt` 或 `vtt`，结果应作为文本保存，不能按 JSON 解析。`verbose_json` 可能包含分段、时间信息等额外字段，具体结构取决于模型。

## 指定语言和术语

模型支持时，`language` 指定输入音频语言，使用 `zh` 或 `en` 等 ISO 639-1 代码；它不是输出翻译语言。`prompt` 用来提供原语言的术语和上下文，不替代音频本身。

```bash 带术语提示的中文转录
curl --fail-with-body https://api.maxapi.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -F "model=$MAXAPI_AUDIO_MODEL" \
  -F "file=@meeting.mp3" \
  -F "language=zh" \
  -F "prompt=这是一段关于 MaxAPI 接入、API Key 和流式响应的技术讨论。" \
  -F "response_format=json" \
  --output transcription.json
```

确认命令成功后，从 JSON 中读取 `text`，不要依赖存在段落或时间戳字段。

```python 保存转录文字
import json
from pathlib import Path

result = json.loads(Path("transcription.json").read_text(encoding="utf-8"))
text = result.get("text")
if not isinstance(text, str):
    raise ValueError("未收到转录文字，请检查原始响应")
Path("transcript.txt").write_text(text, encoding="utf-8")
print(text)
```

## 保存字幕文件

在支持 SRT 的模型上运行下面的命令。返回的是字幕文本，应保存为 `.srt`，不调用 JSON 解析器。

```bash 保存 SRT 字幕
curl --fail-with-body https://api.maxapi.ai/v1/audio/transcriptions \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -F "model=$MAXAPI_AUDIO_MODEL" \
  -F "file=@meeting.mp3" \
  -F "response_format=srt" \
  --output subtitles.srt
```

仅在命令成功后使用字幕文件。检查时间顺序和实际音频是否对应。`vtt` 同样应按文本处理；`verbose_json` 的分段和时间字段取决于模型，不应假定所有模型都返回相同结构。

## 处理长录音

当录音超出所用模型限制时，在应用中按时间拆分。记录每段的起始时间和顺序，优先在停顿或句子边界附近切分；合并字幕时应给相对时间加上该段起始偏移。若切分时保留了重叠音频，合并文字时需要去除重复内容。

转录成功不等于已经识别说话人。说话人标注和逐词时间戳需要对应模型及协议支持，不能从普通 `text` 输出推导。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 提示缺少文件 | 确认使用 `-F "file=@meeting.mp3"` 上传文件内容 |
| 识别结果为空或错误很多 | 检查音轨是否有效、是否有语音，以及录音质量和语言设置 |
| 字幕格式不支持 | 使用该模型支持的输出格式，先用 `json` 验证 |
| 上传过大 | 按时间切分音频，在应用中记录分段顺序与时间偏移 |

其他认证或上游错误见 [错误排查](/zh/help/errors)。
