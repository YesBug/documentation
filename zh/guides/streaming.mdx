流式响应让应用在生成结束前逐段展示文字。对支持流式输出的模型设置 `stream: true`，然后按顺序读取增量内容。一个可靠的界面还需要区分“正在生成”“已完成”和“中断后仅保留了部分内容”。

## 开始前

先用同一个模型完成一次[普通文本请求](/zh/quickstart)，再启用流式输出。安装 [Python SDK](/zh/guides/python) 或 [Node.js SDK](/zh/guides/nodejs)，并设置 `MAXAPI_API_KEY`、`MAXAPI_MODEL`。

| 普通请求 | 流式请求 |
| --- | --- |
| 等待后读取完整 JSON | 持续接收 `text/event-stream` 事件 |
| 文本在 `choices[0].message.content` | 文本片段在 `choices[0].delta.content` |
| 读取一次 `finish_reason` | 从数据块中记录非空的 `finish_reason` |
| 失败时通常没有完整回答 | 中途失败前可能已显示部分文字 |

## Python：输出文本并检测中断

保存为 `stream.py`。程序保留接收的片段，只有观察到正常结束原因时才报告完成；在异常或用户按 Ctrl+C 后关闭流。

```python stream.py
import os
import sys
import openai
from openai import OpenAI

parts = []
finish_reason = None
stream = None

try:
    with OpenAI(
        api_key=os.environ["MAXAPI_API_KEY"],
        base_url="https://api.maxapi.ai/v1",
        timeout=60.0,
        max_retries=0,
    ) as client:
        stream = client.chat.completions.create(
            model=os.environ["MAXAPI_MODEL"],
            messages=[{"role": "user", "content": "为团队笔记应用写一份简短的上手指南。"}],
            stream=True,
        )
        try:
            for chunk in stream:
                if not chunk.choices:
                    continue
                choice = chunk.choices[0]
                if choice.delta.content:
                    parts.append(choice.delta.content)
                    print(choice.delta.content, end="", flush=True)
                if choice.finish_reason:
                    finish_reason = choice.finish_reason
        finally:
            stream.close()
    if finish_reason != "stop":
        raise RuntimeError(f"未确认完整回答，结束原因：{finish_reason}")
    print("\n生成完成。", file=sys.stderr)
except KeyboardInterrupt:
    print("\n已取消，当前显示的是部分内容。", file=sys.stderr)
except (openai.OpenAIError, RuntimeError) as error:
    print(f"\n流未完成：{type(error).__name__}，结束原因：{finish_reason}", file=sys.stderr)
    sys.exit(1)

text_received = "".join(parts)
```

```bash
python stream.py
```

正常时会逐段打印文本，最后在标准错误中显示“生成完成”。`text_received` 是收到的全部文字；若接入数据库，应结合最终状态决定它是正式回答还是未完成草稿。

## Node.js：支持主动取消

保存为 `stream.mjs`。按 Ctrl+C 会中断本地请求，不会把已显示的片段当成完整回答。

```javascript stream.mjs
import OpenAI from "openai";

const apiKey = process.env.MAXAPI_API_KEY;
const model = process.env.MAXAPI_MODEL;
if (!apiKey || !model) throw new Error("请设置 MAXAPI_API_KEY 和 MAXAPI_MODEL。");
const client = new OpenAI({
  apiKey, baseURL: "https://api.maxapi.ai/v1", timeout: 60_000, maxRetries: 0,
});
const controller = new AbortController();
const cancel = () => controller.abort();
process.once("SIGINT", cancel);
const parts = [];
let finishReason = null;

try {
  const stream = await client.chat.completions.create({
    model,
    messages: [{ role: "user", content: "为团队笔记应用写一份简短的上手指南。" }],
    stream: true,
  }, { signal: controller.signal });

  for await (const chunk of stream) {
    const choice = chunk.choices[0];
    if (choice?.delta.content) {
      parts.push(choice.delta.content);
      process.stdout.write(choice.delta.content);
    }
    if (choice?.finish_reason) finishReason = choice.finish_reason;
  }
  if (controller.signal.aborted || finishReason !== "stop") {
    throw new Error("未确认完整回答。");
  }
  console.error("\n生成完成。");
} catch (error) {
  console.error("\n", controller.signal.aborted ? "已取消，内容不完整。" : "流未完成。",
    "结束原因：", finishReason);
  process.exitCode = 1;
} finally {
  controller.abort();
  process.off("SIGINT", cancel);
}
const textReceived = parts.join("");
```

```bash
node stream.mjs
```

示例中的 60 秒是客户端超时配置，不是整个服务的生成时限。取消会关闭客户端等待，不能据此认定服务端没有处理或不会计费。

## 用 cURL 观察原始事件

`curl -N` 禁用 curl 输出缓冲，`jq` 负责安全构造请求 JSON。

```bash cURL · 需要 jq
jq -n --arg model "$MAXAPI_MODEL" '{
  model: $model,
  messages: [{role: "user", content: "用三句话解释什么是 API。"}],
  stream: true
}' | curl -N --fail-with-body https://api.maxapi.ai/v1/chat/completions \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @-
```

下面是简化的 SSE 事件示意，省略了其他元信息；它不是一次实际调用的记录：

```text
data: {"choices":[{"index":0,"delta":{"role":"assistant"},"finish_reason":null}]}

data: {"choices":[{"index":0,"delta":{"content":"API "},"finish_reason":null}]}

data: {"choices":[{"index":0,"delta":{"content":"是一种接口。"},"finish_reason":null}]}

data: {"choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: [DONE]
```

事件实际以 `data:` 开头，事件之间用空行分隔。`[DONE]` 是结束标记，不是需要 JSON 解析的对象。SDK 会处理 SSE 封装，你读取的是解析后的数据块。

<Note>
一次网络读取不等于一个 SSE 事件：一个事件可能拆成多段读取，多个事件也可能合并到一段。自行解析时先进行增量 UTF-8 解码，再按事件边界拆分，不能直接对每个网络分块执行 `JSON.parse`。
</Note>

## 处理非文本数据块

- 有些数据块只携带角色、结束原因或其他信息，`delta.content` 为空是正常的。
- `choices` 可能为空，读取前先检查；不要假设每个块都具有候选文本。
- 不要依赖固定分块大小，也不要假设每块恰好是一个 token 或一个完整单词。
- `usage` 是否出现及其字段取决于接口与模型。没有返回时不要把它当作零用量。
- 工具参数可能以 `delta.tool_calls` 片段返回。按候选和调用索引分别累积名称、ID 与参数，等该调用结束后再解析 JSON 和执行工具。完整流程见[工具调用](/zh/guides/tools)。

## 界面状态与故障处理

| 情况 | 应用行为 |
| --- | --- |
| 还未收到文本 | 展示等待状态；不要把空的角色块当成空回答 |
| 持续收到文本 | 按顺序追加，保留当前输出 |
| 结束原因为 `stop` | 标记生成完成 |
| 结束原因为 `length` | 标记输出可能被截断，提供明确的重新生成或继续操作 |
| 用户取消 | 关闭连接并标记取消，保留片段供用户查看 |
| 网络断开或没有结束原因 | 标记未完成，不要悄悄当成成功保存 |

如果 cURL 能逐段收到内容，但你的网页一次性显示全部结果，检查应用是否先聚合完整响应，以及中间代理是否缓冲输出。断流后直接重试会产生一次新的生成；不要把新回答追加到旧回答后伪装成续传。
