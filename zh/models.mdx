调用 MaxAPI 时，通过请求中的 `model` 指定目标模型。使用控制台或模型列表返回的准确 ID，可以避免模型名称、展示名称与 API 标识之间的混淆。

## 查询模型

[模型总览](https://platform.maxapi.ai/modelmak) 适合浏览模型信息；应用配置和权限验证则使用下面的模型列表接口。公开模型展示与某个密钥实际可访问的范围可能不同。

```bash 列出可见模型
curl --fail-with-body https://api.maxapi.ai/v1/models \
  -H "Authorization: Bearer $MAXAPI_API_KEY"
```

模型列表的兼容结构包含 `data` 数组，每一项中的 `id` 用于后续请求。具体响应以实时接口为准，参见 [模型列表接口](/zh/api-reference/models)。

如果已安装 `jq`，可以只输出模型 ID：

```bash
curl --fail-with-body https://api.maxapi.ai/v1/models \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  | jq -r '.data[]?.id'
```

## 按任务验证能力

模型之间的输入类型、参数支持和输出行为可能不同。建议先用少量有代表性的真实任务验证，再将模型用于生产流量。

| 验证维度 | 建议检查 |
| --- | --- |
| 任务质量 | 是否能遵循你的指令，处理目标语言和业务内容 |
| 响应速度 | 首次返回内容的时间与完整生成耗时 |
| 上下文 | 输入历史和预期输出是否处于模型允许的范围内 |
| 输入类型 | 是否支持任务需要的文本、图片或其他输入 |
| 高级能力 | 是否支持工具调用、结构化输出等所需功能 |
| 成本 | 当前模型计费方式与实际用量是否符合预算 |

模型列表并不一定包含完整能力说明。价格、上下文长度、限额和访问条件，以控制台及对应模型说明为准。

## 把模型 ID 配置化

将模型 ID 放在环境变量中，可以在不修改业务代码的情况下切换模型：

```bash
export MAXAPI_MODEL="替换为模型 ID"
```

```python
response = client.chat.completions.create(
    model=os.environ["MAXAPI_MODEL"],
    messages=[{"role": "user", "content": "请总结这段内容。"}],
)
```

这段代码使用已配置的 `client`；完整初始化示例见 [Python SDK](/zh/guides/python)。

## 切换模型时重新检查参数

先用 `model` 和 `messages` 验证基础调用，再逐个加入流式响应、采样参数或输出限制。一个模型接受的字段和值不一定适用于另一个模型。

当出现“不支持的参数”或类似错误时，应根据目标模型说明调整字段。不要仅因为接口协议兼容，就假定所有模型的功能完全一致。

## 按任务选择模型和协议

| 任务 | 模型能力 | 常见接口 |
| --- | --- | --- |
| 文本对话 | 文本输入与生成 | [Chat Completions](/zh/api-reference/chat-completions) |
| 图片理解 | 多模态视觉输入 | [图像理解](/zh/guides/vision) |
| 调用应用函数 | 工具调用 | [工具调用](/zh/guides/tools) |
| 生成图片或编辑图片 | 图像生成或图像编辑 | [Images](/zh/api-reference/images) |
| 文本检索与相似度 | 向量生成 | [Embeddings](/zh/api-reference/embeddings) |
| 合成语音 | 文本转语音 | [Speech](/zh/api-reference/audio-speech) |
| 识别录音 | 语音转文本 | [转录与翻译](/zh/api-reference/audio-transcriptions) |
| 视频或音乐 | 对应异步生成通道 | [多媒体接入](/zh/media/index) |

不要把聊天模型 ID 用作嵌入、图像或音频模型。原生协议的模型选择方式也可能不同，例如 Suno 使用 `mv`，部分 Veo 路径直接包含模型名。

模型目录只提供部分线索。它不能证明一个模型同时支持所有输入格式、工具调用、原生路由或同样的参数范围。完整的格式选择方式见 [选择接口格式](/zh/guides/protocols)。

## 上线前做一张能力记录表

为实际选用的每个模型保存测试记录，避免模型切换后业务功能悄悄变化：

| 项目 | 要记录的结果 |
| --- | --- |
| 模型 ID 与测试日期 | 使用的准确标识；访问权限可能随账户配置变化 |
| 基础文本 | 最小请求是否成功，返回结构能否被应用正确处理 |
| 多轮与角色 | 历史是否保留，业务指令使用的角色是否受支持 |
| 流式输出 | 是否有内容增量、明确结束状态，取消后如何处理 |
| 图片与工具 | 只测试业务需要的能力，记录输入格式与失败情况 |
| 参数 | 接受的字段和值；是否有模型专有参数 |
| 质量与耗时 | 固定测试集上的任务成功率、首段延迟与完整耗时 |
| 用量与成本 | 返回的用量字段和控制台的实际计费记录 |

这是一份应用侧验收记录，不是服务端能力声明。通过它可以判断某次失败来自模型差异、参数变化还是你的集成代码。

## 如何理解用量和费用

Chat Completions 的 `usage` 通常使用 `prompt_tokens`、`completion_tokens` 和 `total_tokens` 表示输入、输出与总用量。Token 不等于字符数：语言、分词方式、图片输入和模型行为都会影响计量。

- 多轮对话每次重新提交的历史会成为本次输入，历史越长，输入用量可能越高。
- `usage` 是用量信息，不是货币金额；不能直接把 `total_tokens` 当成费用。
- 如果目标模型按输入和输出 token 分别计价，用各自的实际用量乘以对应单价，再按公布的计价单位换算。
- 图像、音频、视频和音乐可能采用不同的计费单位；不要套用文本 token 公式。
- 缓存命中、折扣、失败请求与重试如何计费，应核对该模型和账户的具体规则，不能从一次响应推断。

查询当前单价时，登录后打开 [模型价格费率说明](https://platform.maxapi.ai/account/pricing)。查询当次实际费用时，以控制台的模型说明和计费记录为准。建议把响应 ID、模型、时间和用量关联起来，方便对账；文档不提供未经核实的统一价格表。

## 当模型列表与实际调用不一致

先确认查询模型和生成请求使用同一个 API Key、同一个账户环境，再核对接口类型、完整模型 ID 和请求参数。若最小请求仍然失败，记录脱敏错误正文与请求时间，按 [错误排查](/zh/help/errors) 中的信息模板反馈。
