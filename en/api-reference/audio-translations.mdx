The audio translation endpoint produces English text from an uploaded recording. It is not a general target-language selector. Use a model that explicitly supports this MaxAPI endpoint.

## Submit a file

Set `MAXAPI_AUDIO_MODEL` to a translation-capable model and upload an actual file. Do not set `language` to choose a target language:

```bash Translate a recording
curl --fail-with-body https://api.maxapi.ai/v1/audio/translations \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -F "model=$MAXAPI_AUDIO_MODEL" \
  -F "file=@meeting.mp3" \
  -F "response_format=json"
```

The HTTP client generates the multipart boundary. File encoding, size and duration restrictions depend on the selected model and channel. Use an English `prompt` if the model supports contextual hints.

## Save the English translation

Add `--output translation.json` to the cURL command above. After it succeeds, save `text` as UTF-8 with this script.

```python Save translated text
import json
from pathlib import Path

result = json.loads(Path("translation.json").read_text(encoding="utf-8"))
text = result.get("text")
if not isinstance(text, str):
    raise ValueError("No English translation; inspect the original response")
Path("translation-en.txt").write_text(text, encoding="utf-8")
print(text)
```

This illustrative response explains the format; its sentence is not the result of a real recording.

```json Example JSON result
{"text": "The meeting will begin at ten tomorrow morning."}
```

## Translate into another language

For Japanese, Chinese or another target language, use two steps. First [transcribe](/en/api-reference/audio-transcriptions) the source and save it as `transcript.txt`. Then use a chat model supporting the target language to translate the text. This also retains the source for quality checks.

This command requires `jq`. `--rawfile` reads the transcript and safely constructs JSON even when the text contains quotes or newlines.

```bash Translate the transcript into Japanese
jq -n --arg model "$MAXAPI_MODEL" --rawfile transcript transcript.txt '{
  model: $model,
  messages: [{
    role: "user",
    content: ("Translate this audio transcript into Japanese. Preserve proper names and paragraphs. Return only the translation:\n\n" + $transcript)
  }]
}' | curl --fail-with-body https://api.maxapi.ai/v1/chat/completions \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @-
```

The second result is in `choices[].message.content`, not the audio endpoint's `text`. Each step creates its own request and usage. Long transcripts must also fit the chat model's context.

| Goal | Workflow |
| --- | --- |
| Preserve the recording's language | Audio transcription |
| Produce English directly | This audio translation endpoint |
| Produce another target language | Transcribe, then translate the text with chat |
| Read the translation aloud | Send the translated text to [speech generation](/en/api-reference/audio-speech) |

## Read the translation

For JSON output, read the translated English content from `text`. For supported `text`, `srt` or `vtt` output, read the response as text. Do not assume every model supports every output format.

For a different target language, [transcribe](/en/api-reference/audio-transcriptions) the recording first, then translate the recognized text using [Chat Completions](/en/api-reference/chat-completions).

## Troubleshoot uploads and output

Use `@` in the cURL file argument to send bytes rather than a path string. Verify the recording contains speech and its encoding matches the extension. Split large recordings while preserving segment order and timestamps. Start with a minimal request if optional formatting or sampling parameters are rejected.

See [transcription](/en/api-reference/audio-transcriptions) for related file handling and [troubleshooting](/en/help/errors) for HTTP failures.
