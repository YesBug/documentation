The Completions endpoint continues a `prompt` for existing integrations using the legacy format. It differs from [Chat Completions](/en/api-reference/chat-completions), which accepts `messages`. Confirm your model supports this endpoint before calling it.

## Complete a text prompt

Configure `MAXAPI_API_KEY` and set `MAXAPI_MODEL` to a completion-capable model. This `jq` example sends only required fields.

```bash Complete a prompt
jq -n --arg model "$MAXAPI_MODEL" '{
  model: $model,
  prompt: "Continue this product introduction: MaxAPI helps developers"
}' | curl --fail-with-body https://api.maxapi.ai/v1/completions \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @- \
  --output completion-response.json
```

After the command succeeds, read `choices[].text`. Treat it as the generated completion; do not depend on it including your original `prompt`.

```python Read completion results
import json
from pathlib import Path

result = json.loads(Path("completion-response.json").read_text(encoding="utf-8"))
if not result.get("choices"):
    raise ValueError("No completion returned; inspect the original response")
for choice in result["choices"]:
    print("Candidate:", choice.get("index"))
    print(choice.get("text", ""))
    print("Finish reason:", choice.get("finish_reason"))
print("Usage:", result.get("usage", {}))
```

A `length` finish reason indicates a generation limit, so the output may be incomplete. Where supported, `max_tokens` sets the requested output cap; it is not a platform-wide quota.

## Compare with Chat Completions

| Stage | Completions | Chat Completions |
| --- | --- | --- |
| Input | A `prompt` string; string batches require support | Ordered `messages` |
| Regular output | `choices[].text` | `choices[].message.content` |
| Streaming text | `choices[].text` | `choices[].delta.content` |
| Conversation history | Application assembles the complete prompt | Application retains roles and message history |
| Tools and images | Chat fields cannot be copied directly | Requires corresponding chat capabilities |

For a new chat application, start with the message-based interface. Migrating an existing completion integration requires updating both request construction and result parsing, not just the URL.

## Stream completions

Add `stream: true` and use `curl -N` to observe events, or use an SSE-aware client. Each event's `choices[].text` contains a fragment. Assemble fragments separately for each candidate `index`.

Check the finish reason at completion. Do not parse every network chunk as JSON because a chunk need not contain a complete SSE event. Follow the event framing in [streaming](/en/guides/streaming), replacing the chat text extraction with `choices[].text`.

## Troubleshooting

| Problem | Action |
| --- | --- |
| Listed model rejects the request | Confirm `/v1/completions` support, then test minimal fields |
| Output appears missing | Read `choices[].text`, not `message.content` |
| Chat messages are rejected | Send `prompt`, or use Chat Completions |
| The answer stops mid-sentence | Check finish reason, requested output limit and context size |
| `stop` or `logprobs` is rejected | Remove the option; optional fields are not supported by every model |

See [troubleshooting](/en/help/errors) for other HTTP errors.
