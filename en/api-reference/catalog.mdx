The MaxAPI extended catalog contains **173 operations** preserved from a sanitized shared-system export. Use it to locate methods, paths and declared fields. It is a structural reference, **not a statement that every endpoint is enabled for MaxAPI or your account**, and not a record of successful live tests.

Start with the [core API reference](/en/api-reference/index) for documented interactive endpoints, or [multimedia guides](/en/media/index) for task workflows. Use page search to locate a provider, method or path in this catalog.

## Read the status labels

| Label | Meaning |
| --- | --- |
| Protocol reference | Useful for locating an operation and checking fields; confirm model and channel access |
| Needs review | Source definitions are incomplete, conflicting or ambiguous |
| Example path | The source contains a literal sample or placeholder; verify the real route before calling it |

Authentication values, original request examples, third-party file addresses and prices were removed from the source catalog. Two fixed example identifiers have been replaced with `{example_file_id}` and `{example_task_id}`. An absent authentication definition does not imply anonymous access; follow [MaxAPI authentication](/en/authentication).

## Use the correct base URL

Compatible SDKs use `https://api.maxapi.ai/v1`. For a confirmed native route, append its path to `https://api.maxapi.ai` without automatically adding `/v1`. Keep query methods, IDs and result handling aligned with the selected [protocol](/en/guides/protocols).

Field requirements and types below reproduce the structural export, including known limitations. They are not substitutes for a confirmed channel contract. **Not specified in source** means the definition was missing, not that the endpoint accepts no parameters.
