These answers address common MaxAPI setup and integration questions. For a failed request with an HTTP status or task error, use the [troubleshooting guide](/en/help/errors).

<AccordionGroup>
  <Accordion title="How do the website, console and API addresses differ?">
    Use [maxapi.ai](https://maxapi.ai) for product information and [platform.maxapi.ai](https://platform.maxapi.ai) to manage your account and keys. Applications call `https://api.maxapi.ai`. For a compatible SDK, set the base URL to `https://api.maxapi.ai/v1`.
  </Accordion>
  <Accordion title="Can I keep using the OpenAI SDK?">
    You can use it for the Chat Completions-compatible flow documented here. Configure the MaxAPI key, base URL and an available model ID together. Compatibility with one endpoint does not imply support for every SDK method. See the [Python](/en/guides/python) and [Node.js](/en/guides/nodejs) guides.
  </Accordion>
  <Accordion title="Which model name should I send?">
    Use the exact `id` returned by [List models](/en/api-reference/models), and confirm it suits your endpoint. Do not assume a display name or another platform's ID is valid on MaxAPI.
  </Accordion>
  <Accordion title="Why do examples use MAXAPI_MODEL?">
    An environment variable keeps examples usable across accounts and makes model changes configurable. Set it to a real model ID available to your account before running an example.
  </Accordion>
  <Accordion title="Why is my key missing even though I created a .env file?">
    A `.env` file does not change every process environment automatically. Load it with your framework, runtime or environment loader, or export the variable before starting your program. Do not print a real key while debugging.
  </Accordion>
  <Accordion title="Should my browser call the API directly?">
    Prefer sending browser requests to your backend, where the key is managed. Keys in frontend code or public environment variables are visible to visitors. See [authentication](/en/authentication). The documentation's [interactive testing](/en/playground) is a separate testing workflow using Mintlify's playground.
  </Accordion>
  <Accordion title="How do I continue a conversation?">
    Include the relevant history in the next request's `messages`. Do not expect the client object to remember it automatically. Trim or summarize long histories according to the model's context limits.
  </Accordion>
  <Accordion title="Why does streaming not display one character at a time?">
    Enable `stream: true`, read increments as they arrive and check application buffering. A model can send multiple characters in one chunk; one character per event is not guaranteed. See [streaming](/en/guides/streaming).
  </Accordion>
  <Accordion title="Where can I find prices, balance and usage?">
    Use the [model overview](https://platform.maxapi.ai/modelmak) for model information and sign in to the [pricing page](https://platform.maxapi.ai/account/pricing) for current prices. Check your balance and usage records in the console. Examples in these docs do not establish prices, quotas, service commitments or current model availability.
  </Accordion>
  <Accordion title="What should I include in a support request?">
    Provide the time and time zone, model ID, route, HTTP status and redacted error details through the console's support entry. Remove keys and sensitive data first. See [troubleshooting](/en/help/errors).
  </Accordion>
  <Accordion title="Which API format should I use for a model?">
    Choose an enabled format suited to the task: compatible chat for conversations, or unified and provider-specific formats for video tasks. Keep the base URL, body and task query format aligned. See [API formats](/en/guides/protocols).
  </Accordion>
  <Accordion title="Why did a music or video request return no file?">
    These are commonly asynchronous tasks. Save the returned identifier and query the task or receive a supported callback. Identifier and terminal-state fields differ between protocols. See [asynchronous tasks](/en/guides/async-tasks).
  </Accordion>
  <Accordion title="Can I call every endpoint in the extended catalog?">
    Not necessarily. The [catalog](/en/api-reference/catalog) indexes the shared system's structure. Availability depends on your account's models and channels. Entries marked Needs review or Example path require additional validation. The catalog is not a record of live MaxAPI verification.
  </Accordion>
</AccordionGroup>

## Why does generation fail after model listing succeeds?

Listing only establishes that the key can perform that query. Chat, images, audio and embeddings need their respective model capabilities. Verify the endpoint, test minimal fields, then add options individually. A model ID's presence does not imply support for every interface.

## Why does a playground request fail after I copy it into code?

Compare the final URL, key source, model ID and body. Check for a duplicate `/v1`, unloaded environment variables and files missing from the server environment. The playground uses a documentation proxy, while your server has its own network path. See [online testing](/en/playground).

## Does HTTP 200 mean generation is complete?

Inspect the result too. Chat needs `choices` and a suitable finish reason; tools require application execution. Video or music submission can return only an ID and still require terminal-state queries. Audio and subtitles need the correct response reader. See the [API overview](/en/api-reference/index).

## Should I use max_tokens or max_completion_tokens?

Use the parameter explicitly supported by the model, never both together. They are not interchangeable on every model, and some generation budgets can include reasoning tokens. Test without a length option first, then add the model's supported control.

## Can I convert usage directly into a charged amount?

`usage` is reported consumption, not a universal billing formula. Fields vary by model, and image, audio or asynchronous work cannot all be priced using chat token counts. Consult current console prices, charges and account records.

## Should I immediately resend a timed-out request?

A timeout means the client did not receive a complete result within its deadline; it does not prove the server did no work. Check an existing task ID, queryable status or console record first. Retry a bounded number of times only when appropriate to avoid duplicate generation.

## How do I save images when the API returns only Base64?

Decode `data[].b64_json` into bytes and save them using the actual file format. Writing the Base64 string directly to a PNG file will not create an image. See [image generation](/en/api-reference/images) for complete batch URL and Base64 handling.

## Why does an audio response fail JSON parsing?

Speech generation returns audio bytes. Transcription and translation can return subtitle text. Only JSON output belongs in a JSON parser. Check HTTP status and Content-Type, then select a reader. See [speech](/en/api-reference/audio-speech) and [transcription](/en/api-reference/audio-transcriptions).

## Can audio translation directly output Japanese or Chinese?

The documented `/v1/audio/translations` endpoint outputs English. For another target language, transcribe the original recording and translate the text with a chat model. To speak the result, pass the translation to speech generation. See [audio translation](/en/api-reference/audio-translations) for runnable examples.

## Are example timeouts, batch sizes and dimensions platform limits?

No. Values marked as examples illustrate client integration choices. Actual capabilities, input sizes, rates and other limits depend on the model and account configuration. Do not infer universal platform limits from sample code.
