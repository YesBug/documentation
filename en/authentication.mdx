MaxAPI authenticates requests with API keys. Send requests over HTTPS and pass your key in the `Authorization` header.

## Send a Bearer token

```http Authorization header
Authorization: Bearer YOUR_MAXAPI_API_KEY
```

Keep one space between `Bearer` and the key. Do not place keys in URL query strings or print full keys in logs.

```bash Check the connection
curl --fail-with-body https://api.maxapi.ai/v1/models \
  -H "Authorization: Bearer $MAXAPI_API_KEY"
```

A successful model list helps verify your key and network configuration. It does not confirm that all models support the same parameters or share the same access permissions.

## Store keys on your server

During local development, you can store a key in `.env`. Your runtime or an environment loader must read the file:

```dotenv .env
MAXAPI_API_KEY=YOUR_MAXAPI_API_KEY
MAXAPI_MODEL=YOUR_MODEL_ID
```

Ignore files containing real keys in Git. You can commit an `.env.example` containing only placeholders:

```text .gitignore
.env
.env.*
!.env.example
```

For deployed applications, use your hosting platform's environment variables or secret manager. Avoid prefixes such as `NEXT_PUBLIC_` and `VITE_` that expose values to browsers.

## Load configuration from .env

Create `.env` using the format above, replace the key and model placeholders, then choose the loader for your runtime. These checks print whether configuration exists without making API requests.

<Tabs>
<Tab title="Python">

Install the loader in the same virtual environment that runs your application:

```bash Install python-dotenv
python -m pip install python-dotenv
```

Save this file beside `.env`. If your interpreter is named `python3`, use it for both installation and execution.

```python check_env.py
import os
from pathlib import Path
from dotenv import load_dotenv

load_dotenv(Path(__file__).with_name(".env"), override=False)

print("API key configured:", bool(os.environ.get("MAXAPI_API_KEY")))
print("Model configured:", bool(os.environ.get("MAXAPI_MODEL")))
```

```bash Check configuration
python check_env.py
```

In your application, put `load_dotenv(...)` and its imports before reading `os.environ` or creating an SDK client. Running the check separately does not load configuration for another Python process. This example explicitly selects `.env` beside the script and uses `override=False` to preserve existing environment values. See the [python-dotenv documentation](https://bbc2.github.io/python-dotenv/).

</Tab>
<Tab title="Node.js">

Save this file beside `.env` and run the commands from that directory:

```javascript check_env.mjs
console.log("API key configured:", Boolean(process.env.MAXAPI_API_KEY));
console.log("Model configured:", Boolean(process.env.MAXAPI_MODEL));
```

```bash Check version and configuration
node --version
node --env-file=.env check_env.mjs
```

[`--env-file` is available from Node.js v20.6.0](https://nodejs.org/api/cli.html#--env-filefile). Your installed SDK may require a newer runtime. The path is relative to the command's working directory; place the flag before the script name. A missing file causes an error.

For the [quickstart](/en/quickstart), run `node --env-file=.env hello.mjs`. Running only `node hello.mjs` does not inherit configuration loaded by a previous check process.

</Tab>
</Tabs>

Both loaders preserve environment values already set for the process. If editing `.env` does not change the key your application uses, check for the same variable in your terminal, IDE or hosting configuration, then restart the application. Loading a file configures that program; it does not export variables to later cURL commands in your terminal. For cURL, use the terminal environment setup in the [quickstart](/en/quickstart).

## Configure a compatible client

<CodeGroup>

```python Python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["MAXAPI_API_KEY"],
    base_url="https://api.maxapi.ai/v1",
)
```

```javascript Node.js
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: process.env.MAXAPI_API_KEY,
  baseURL: "https://api.maxapi.ai/v1",
});
```

</CodeGroup>

Always configure the MaxAPI base URL when using a MaxAPI key.

## Rotate and revoke keys

Manage separate keys for different applications and environments where your console supports this. Configure access scopes using the controls available to your account.

To rotate a key, create a replacement, update your application configuration, verify a successful request, then revoke the old key. If a key is exposed, revoke it promptly, replace affected configuration and review related usage records.

## Resolve authentication failures

For a `401` response, check that:

- Your environment variable reached the process actually running the application.
- The key has no accidental spaces, line breaks or extra quotation marks.
- The request includes the full `Authorization: Bearer ...` header.
- The key is still valid and belongs to the MaxAPI account you are using.

If authentication succeeds but a model request fails, check [model capabilities](/en/models) and [troubleshooting](/en/help/errors).

## Connect a browser application

Use the flow `Browser → Your server → MaxAPI`. The browser calls your application using its own login session. Your server reads the MaxAPI key from its environment and constructs the API request. This also lets you apply per-user limits, restrict model choices and track business usage.

Do not blindly forward arbitrary URLs, authorization headers or unrestricted model parameters supplied by a browser. Expose only the endpoints your application needs and validate user identity, input length and allowed parameters.

The [documentation playground](/en/playground) is for manual development tests. Your product should use its own server-side credential management.

## Check configuration without printing the key

Environment variables affect the current process and child processes started afterward. After [loading configuration](#load-configuration-from-env), run these checks inside the actual application process. Checking a separate terminal alone does not establish what the application receives:

<CodeGroup>
```python Python
import os

print("API key configured:", bool(os.environ.get("MAXAPI_API_KEY")))
```
```javascript Node.js
console.log("API key configured:", Boolean(process.env.MAXAPI_API_KEY));
```
</CodeGroup>

A true result only confirms a nonempty value is present in the process. Verify authentication with `GET /v1/models` next; printing parts of the key is not a substitute for request verification.

## Manage environments and teams

| Environment | Recommended practice |
| --- | --- |
| Local development | Use a development key; keep personal production keys out of examples |
| CI and deployment | Use CI secret settings and prevent command echoing or build artifacts from exposing keys |
| Production services | Read deployment secret configuration and confirm updates reach every instance |
| Support investigations | Share redacted requests, timestamps and response identifiers, never complete keys |

If a key leaks, revoke it and update the application first, then review usage records. Deleting the plaintext from code does not revoke an exposed credential. Git history and build logs may retain old values.
