Connect MaxAPI text generation to a runnable Python program. Configure the client, read generated text and usage, and distinguish connection failures, timeouts, and API errors.

## 1. Install the SDK

Create a virtual environment to keep dependencies separate from other projects.

<CodeGroup>
```bash macOS / Linux
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade openai
```

```powershell Windows PowerShell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade openai
```
</CodeGroup>

Run `python -m pip show openai` to check the installed version in this environment. Test SDK upgrades before updating an existing production application.

## 2. Set your key and model

Get an API key from the [console](https://platform.maxapi.ai), then choose an accessible text model ID from the [model list](/en/api-reference/models).

<CodeGroup>
```bash macOS / Linux
export MAXAPI_API_KEY="YOUR_API_KEY"
export MAXAPI_MODEL="YOUR_MODEL_ID"
```

```powershell Windows PowerShell
$env:MAXAPI_API_KEY = "YOUR_API_KEY"
$env:MAXAPI_MODEL = "YOUR_MODEL_ID"
```
</CodeGroup>

These variables apply to the current terminal and programs started from it. The example does not load `.env` files automatically. When running from an IDE, set the variables in its run configuration too.

## 3. Save and run the complete program

Save this as `main.py`. It sets a 60-second client timeout and disables SDK retries so you can observe each request while integrating. These are application choices, not MaxAPI service limits.

```python main.py
import os
import sys
import openai
from openai import OpenAI

api_key = os.environ.get("MAXAPI_API_KEY")
model = os.environ.get("MAXAPI_MODEL")
if not api_key or not model:
    raise SystemExit("Set MAXAPI_API_KEY and MAXAPI_MODEL.")

try:
    with OpenAI(
        api_key=api_key,
        base_url="https://api.maxapi.ai/v1",
        timeout=60.0,
        max_retries=0,
    ) as client:
        response = client.chat.completions.create(
            model=model,
            messages=[{
                "role": "user",
                "content": "Write a product description for a team notes app in under 50 words.",
            }],
        )
    if not response.choices:
        raise RuntimeError("The response contains no choices.")
    choice = response.choices[0]
    if choice.message.tool_calls:
        raise RuntimeError("Received tool calls; use the tool-calling flow.")
    print(choice.message.content or "")
    print(f"response_id={response.id}", file=sys.stderr)
    print(f"finish_reason={choice.finish_reason}", file=sys.stderr)
    if response.usage:
        print(f"usage={response.usage.model_dump()}", file=sys.stderr)
except openai.APITimeoutError:
    raise SystemExit("Request timed out; the server may still have processed it.")
except openai.APIConnectionError:
    raise SystemExit("Connection failed. Check the network, proxy, and API address.")
except openai.APIStatusError as error:
    raise SystemExit(f"API request failed: HTTP {error.status_code}. See troubleshooting.")
```

```bash Run
python main.py
```

The terminal prints a generated product description; wording can vary. Diagnostics go to standard error. Generated text is in `response.choices[0].message.content`. A `finish_reason` of `length` means the answer may be truncated. See [text generation](/en/guides/text-generation).

## 4. Understand the client settings

| Setting | Example value | Purpose |
| --- | --- | --- |
| `api_key` | `MAXAPI_API_KEY` | The SDK adds the authorization header; do not prefix the key with `Bearer` |
| `base_url` | `https://api.maxapi.ai/v1` | The SDK appends `/chat/completions` to this address |
| `timeout` | `60.0` | Client timeout configuration, in seconds |
| `max_retries` | `0` | Disables SDK retries so the application decides whether to try again |

Do not use the full `.../v1/chat/completions` endpoint as `base_url`, or append `/v1` twice. Start with only `model` and `messages`; add optional parameters after the minimal request succeeds and model support is confirmed.

The SDK can retry some connection and temporary service errors. If you enable retries, account for each attempt's timeout, total elapsed time, and potentially repeated generation. Avoid multiplying retries in the application layer. Respect a valid `Retry-After` response when supplied. Key, permission, balance, and invalid-parameter errors require fixing their cause first.

## 5. Use the asynchronous client

Use `AsyncOpenAI` inside an asynchronous web service or an `asyncio` program to avoid blocking the event loop with synchronous network calls. Save this as `async_main.py` and use the same environment variables.

```python async_main.py
import asyncio
import os
from openai import AsyncOpenAI

async def main():
    async with AsyncOpenAI(
        api_key=os.environ["MAXAPI_API_KEY"],
        base_url="https://api.maxapi.ai/v1",
        timeout=60.0,
        max_retries=0,
    ) as client:
        response = await client.chat.completions.create(
            model=os.environ["MAXAPI_MODEL"],
            messages=[{"role": "user", "content": "Suggest three names for a team notes app."}],
        )
        if not response.choices:
            raise RuntimeError("The response contains no choices.")
        print(response.choices[0].message.content or "")

if __name__ == "__main__":
    asyncio.run(main())
```

```bash Run the async example
python async_main.py
```

In an existing asynchronous service, `await` the call directly. Do not call `asyncio.run()` inside an active event loop. Asynchronous calls do not increase account limits; bound concurrency according to application needs.

## Troubleshooting

| Symptom | Check first |
| --- | --- |
| `ModuleNotFoundError: openai` | Install and run with the same Python interpreter; check with `python -m pip show openai` |
| Missing environment variables | Use the same terminal; ensure the IDE or background service receives the variables |
| 401 or 403 | Verify the MaxAPI key and access to the requested model |
| 404 | Check `base_url` and duplicated path segments, then the model ID |
| 400 or unsupported parameter | Remove optional parameters, send a minimal request, then add them one at a time |
| Successful connection but no text | Inspect `choices`, `tool_calls`, and `finish_reason` |
| Repeated timeouts | Distinguish connection failures from response waits, check network and model latency, then adjust application timeouts |
