Suno offers multiple compatible formats. Choose an enabled format for the entire workflow and save task IDs separately from song clip IDs. The music model version uses `mv`; valid values come from your [console](https://platform.maxapi.ai) or channel configuration.

## Compare the two common formats

| Detail | Suno v2 | NewAPI-compatible |
| --- | --- | --- |
| Submit | `POST /suno/v2/generate` | `POST /suno/submit/music` |
| Query | `GET /suno/v2/feed?ids=...` | `GET /suno/fetch/{task_id}` |
| Query identifier | `clips[].id`, a song clip ID | Submission `data` string or `data.task_id`, a task ID |
| Query result | `clips[]` | Task object `data`; music results in `data.data[]` |
| Completion check | Check every clip | Check task state, then songs |

The `feed` query takes clip IDs, not a generation response's top-level `id` or a NewAPI `task_id`.

## Configure the examples

The terminal examples use Bash, `curl`, `jq`, and Python 3. Request blocks stop on failure. Put the Bash steps for your chosen workflow in one script and run them in order so variables such as `TASK_ID` remain available. Save Python examples to their named files. Do not skip ahead after an error. Configure a key and music model version enabled for your account:

```bash
export MAXAPI_API_KEY="YOUR_MAXAPI_API_KEY"
export MAXAPI_SUNO_MODEL="YOUR_ENABLED_SUNO_MODEL"
```

Suno paths start with `/suno`; do not add `/v1`. See the [Suno API overview](/en/api-reference/suno/index) for endpoint selection, parameters, and interactive requests. Replace documentation placeholders with valid input before sending real requests.

## Generate a song with Suno v2

| Field | Type | Use | Meaning |
| --- | --- | --- | --- |
| `mv` | `string` | Required | Enabled music model version |
| `prompt` | `string` | Required | Content for the chosen mode; custom songs commonly use lyrics |
| `tags` | `string` | Optional | Musical style |
| `title` | `string` | Optional | Song title |
| `continue_clip_id` | `string` | Continuation | Original clip to extend |
| `continue_at` | `number` | As required for continuation | Position in seconds |

Audio uploads, instrumental modes and other advanced tasks can need additional fields or model versions. This example demonstrates a custom song, not every generation mode together:

```bash Generate a custom song
set -euo pipefail
: > suno-generate.json
: > suno-v2-ready.json
: "${MAXAPI_SUNO_MODEL:?Set an enabled Suno mv value}"
jq -n --arg mv "$MAXAPI_SUNO_MODEL" '{
  mv: $mv,
  prompt: "[Verse]\nMorning light across the floor\nA new road waits beyond the door\n[Chorus]\nLet the quiet melody\nCarry us where we can see",
  tags: "acoustic pop, warm vocals",
  title: "A new road"
}' | curl --fail-with-body https://api.maxapi.ai/suno/v2/generate \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @- \
  --output suno-generate.json
```

### Save each clip ID

A generation response can contain both top-level `id` and `clips[].id`:

```json Illustrative submission structure
{
  "id": "generation-id",
  "clips": [
    {"id": "song-clip-id", "status": "submitted", "audio_url": ""}
  ]
}
```

Acceptance or completion of an outer wrapper does not mean every audio clip is ready. Query by the song clip IDs:

```bash Query clip IDs
set -euo pipefail
: > suno-v2-feed-response.json
: > suno-v2-ready.json
CLIP_IDS="$(jq -er '[.clips[]?.id] | if length > 0 then if all(.[]; type == "string" and length > 0) then join(",") else error("Invalid clip ID") end else error("Response has no clip IDs") end' suno-generate.json)"
: "${CLIP_IDS:?No clip IDs; stop before querying}"
curl --fail-with-body --get https://api.maxapi.ai/suno/v2/feed \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  --data-urlencode "ids=$CLIP_IDS" \
  --output suno-v2-feed-response.json
```

`ids` accepts comma-separated clip IDs. Inspect each `clips[].status`. The source uses `submitted` for acceptance and `complete` for a finished clip. Verify a usable `audio_url` before delivery, and check cover or video URLs separately.

Preserve unknown states and query within a deadline. Stop on explicit failure or error information. A nonempty `audio_url` alone does not establish that the full song is complete.

### Wait for every requested clip

This script reads `suno-generate.json` from the preceding example and queries every returned clip ID. It verifies that the response contains all expected IDs so one completed song cannot accidentally be treated as a complete batch.

Each lookup saves its raw response to `suno-v2-feed-response.json` before status and JSON checks. Only a complete set of the current requested clips creates `suno-v2-ready.json`. Reruns and errors invalidate any previous ready result.

```bash Install the dependency
python3 -m pip install requests
```

```python wait_for_suno.py
import json
import os
import time
from pathlib import Path

import requests


def wait_for_clips(clip_ids, timeout_seconds=600):
    ready = Path("suno-v2-ready.json")
    ready.unlink(missing_ok=True)
    if not clip_ids or not all(isinstance(x, str) and x.strip() for x in clip_ids):
        raise ValueError("Expected nonempty clip ID strings")
    expected = set(clip_ids)
    headers = {"Authorization": f"Bearer {os.environ['MAXAPI_API_KEY']}"}
    deadline = time.monotonic() + timeout_seconds
    raw = Path("suno-v2-feed-response.json")
    while time.monotonic() < deadline:
        raw.write_text("", encoding="utf-8")
        response = requests.get(
            "https://api.maxapi.ai/suno/v2/feed",
            params={"ids": ",".join(sorted(expected))},
            headers=headers,
            timeout=(10, 30),
        )
        raw.write_text(response.text, encoding="utf-8")
        response.raise_for_status()
        payload = response.json()
        clips = payload.get("clips") if isinstance(payload, dict) else None
        if not isinstance(clips, list) or any(not isinstance(x, dict) for x in clips):
            raise ValueError("Expected a clips array; inspect suno-v2-feed-response.json")
        by_id = {clip["id"]: clip for clip in clips if isinstance(clip.get("id"), str)}
        for clip_id in expected:
            clip = by_id.get(clip_id, {})
            metadata = clip.get("metadata") or {}
            if not isinstance(metadata, dict):
                raise ValueError("Invalid clip metadata")
            if metadata.get("error_type") or metadata.get("error_message"):
                raise RuntimeError(f"Clip {clip_id} failed: {metadata.get('error_message')}")
            print(f"{clip_id}: {clip.get('status', 'not returned yet')}")
        if expected.issubset(by_id) and all(
            by_id[clip_id].get("status") == "complete" for clip_id in expected
        ):
            songs = [by_id[clip_id] for clip_id in sorted(expected)]
            if not all(song.get("audio_url") for song in songs):
                raise RuntimeError("A completed clip has no audio_url")
            ready.write_text(json.dumps({
                "protocol": "v2", "requested_clip_ids": sorted(expected), "clips": songs
            }, ensure_ascii=False, indent=2), encoding="utf-8")
            return songs
        remaining = deadline - time.monotonic()
        if remaining > 0:
            time.sleep(min(5, remaining))
    raise TimeoutError("Clips are not all complete; retain their IDs and query again later")


if __name__ == "__main__":
    Path("suno-v2-ready.json").unlink(missing_ok=True)
    submission = json.loads(Path("suno-generate.json").read_text(encoding="utf-8"))
    clips = submission.get("clips") if isinstance(submission, dict) else None
    if not isinstance(clips, list) or any(not isinstance(x, dict) for x in clips):
        raise ValueError("Invalid submission clips")
    songs = wait_for_clips([clip.get("id") for clip in clips])
    print(f"Completed {len(songs)} clips; saved to suno-v2-ready.json")
```

```bash Wait for every clip
python3 wait_for_suno.py
```

The 5-second interval and 600-second budget are example client policies. An HTTP error stops the script; rerunning after resolving the error queries the original clips. Unrecognized states are not treated as success. The script keeps the latest response and eventually times out.

### Save completed audio

Audio, cover images and video are separate outputs. If you need audio only, download `audio_url` without waiting for an unused video URL. This script sends no MaxAPI key to media hosts:

```python save_suno_audio.py
import json
import mimetypes
import sys
from pathlib import Path
from urllib.parse import urlparse

import requests


def read_json(name):
    return json.loads(Path(name).read_text(encoding="utf-8"))


def songs_for_current_request(mode):
    if mode not in {"v2", "newapi"}:
        raise ValueError("Choose v2 or newapi")
    ready = read_json(f"suno-{mode}-ready.json")
    if not isinstance(ready, dict) or ready.get("protocol") != mode:
        raise ValueError("Wrong result protocol")
    songs = ready.get("clips")
    if not isinstance(songs, list) or not songs or any(not isinstance(x, dict) for x in songs):
        raise ValueError("No validated song array")
    if mode == "v2":
        submission = read_json("suno-generate.json")
        original = submission.get("clips") if isinstance(submission, dict) else None
        if not isinstance(original, list) or not original or any(
            not isinstance(x, dict) or not isinstance(x.get("id"), str) or not x["id"] for x in original
        ):
            raise ValueError("Invalid current v2 submission")
        expected = {x["id"] for x in original}
        if set(ready.get("requested_clip_ids", [])) != expected or {x.get("id") for x in songs} != expected:
            raise ValueError("Ready clips do not match the current v2 submission")
    else:
        submission = read_json("suno-task.json")
        if not isinstance(submission, dict) or submission.get("code") != "success":
            raise ValueError("Invalid current NewAPI submission")
        data = submission.get("data")
        task_id = data if isinstance(data, str) else data.get("task_id") if isinstance(data, dict) else None
        if not isinstance(task_id, str) or not task_id.strip() or ready.get("task_id") != task_id:
            raise ValueError("Ready task does not match the current NewAPI submission")
    for song in songs:
        if not isinstance(song.get("id"), str) or not song["id"] or song.get("status") != "complete":
            raise ValueError("Invalid or incomplete clip")
        metadata = song.get("metadata") or {}
        if not isinstance(metadata, dict) or metadata.get("error_type") or metadata.get("error_message"):
            raise ValueError("Clip contains error information")
        if not isinstance(song.get("audio_url"), str) or urlparse(song["audio_url"]).scheme != "https":
            raise ValueError("Expected an HTTPS audio URL")
    return songs


if __name__ == "__main__":
    if len(sys.argv) != 2:
        raise SystemExit("Usage: python3 save_suno_audio.py v2|newapi")
    mode = sys.argv[1]
    for index, clip in enumerate(songs_for_current_request(mode), start=1):
        # No MaxAPI Authorization header is sent to the media host.
        with requests.get(clip["audio_url"], stream=True, timeout=(10, 60)) as response:
            response.raise_for_status()
            media_type = response.headers.get("Content-Type", "").split(";", 1)[0]
            if not media_type.startswith("audio/") and media_type != "application/octet-stream":
                raise RuntimeError(f"Expected audio bytes, received {media_type!r}")
            extension = mimetypes.guess_extension(media_type) or ".audio"
            output = Path(f"suno-{mode}-{index}{extension}")
            partial = output.with_suffix(output.suffix + ".part")
            with partial.open("wb") as file:
                for chunk in response.iter_content(chunk_size=64 * 1024):
                    if chunk:
                        file.write(chunk)
            if partial.stat().st_size == 0:
                raise RuntimeError("Downloaded audio is empty")
            partial.replace(output)
        print(f"Saved clip {clip['id']} to {output}")
```

```bash Download completed songs
python3 save_suno_audio.py v2
```

A download served as `application/octet-stream` can be saved with a `.bin` extension. Verify the actual format before choosing its extension instead of naming every response `.mp3`. Confirm playback, then return your stored asset URL to the frontend.

## NewAPI: generate, then retrieve the task

The NewAPI-compatible endpoint wraps songs in a task. Start with this complete custom-song example; it does not require an existing song:

```bash Generate the first song
set -euo pipefail
: > suno-task.json
: > suno-newapi-ready.json
: "${MAXAPI_SUNO_MODEL:?Set an enabled Suno mv value}"
jq -n --arg mv "$MAXAPI_SUNO_MODEL" '{
  mv: $mv,
  prompt: "[Verse]\nMorning light across the floor\nA new road waits beyond the door",
  tags: "acoustic pop, warm vocals",
  title: "A new road"
}' | curl --fail-with-body https://api.maxapi.ai/suno/submit/music \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @- \
  --output suno-task.json
```

In custom mode, `prompt` contains lyrics and `tags` describes style. Inspiration mode uses `gpt_description_prompt` to describe a song; request instrumental music with `make_instrumental` where supported. Complete one mode first, then add parameters. See [Submit music](/en/api-reference/suno/submit) for field details.

### Handle both submission envelopes

The successful business code is `"success"`. Standard NewAPI returns a task ID string in `data`; some compatible channels return an object containing `task_id`. Neither shape establishes song completion.

<CodeGroup>

```json Task ID string
{"code": "success", "message": "", "data": "YOUR_TASK_ID"}
```

```json Task object
{"code": "success", "message": "", "data": {"task_id": "YOUR_TASK_ID", "status": "SUBMITTED"}}
```

</CodeGroup>

Run this after the preceding `curl` succeeds. It checks the business code and data type before extracting a string ID instead of always reading `data.task_id`:

```bash Extract the task ID
set -euo pipefail
TASK_ID="$(python3 - <<'PYCODE'
import json
from pathlib import Path

response = json.loads(Path("suno-task.json").read_text(encoding="utf-8"))
if not isinstance(response, dict) or response.get("code") != "success":
    raise SystemExit("Submission failed; inspect suno-task.json")
data = response.get("data")
task_id = data if isinstance(data, str) else data.get("task_id") if isinstance(data, dict) else None
if not isinstance(task_id, str) or not task_id.strip():
    raise SystemExit("No valid task ID in the submission response")
print(task_id)
PYCODE
)"
: "${TASK_ID:?Submission did not return a valid task ID}"
export TASK_ID
```

### Retrieve this task

```bash Retrieve once
set -euo pipefail
: > suno-task-status.json
: > suno-newapi-ready.json
TASK_ID_ESCAPED="$(python3 -c 'import os, urllib.parse; print(urllib.parse.quote(os.environ["TASK_ID"], safe=""))')"
curl --fail-with-body \
  "https://api.maxapi.ai/suno/fetch/$TASK_ID_ESCAPED" \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  --output suno-task-status.json
```

| Field | Interpretation |
| --- | --- |
| `code`, `message` | Check the business result of this lookup first |
| `data.task_id` | Current task ID |
| `data.status` | Task state, such as `SUBMITTED`, `IN_PROGRESS`, or `SUCCESS`; failure variants include `FAIL` and `FAILURE` |
| `data.fail_reason` | Task failure details |
| `data.data` | Music result array; other task types may return an object |
| `data.data[].id` | Song clip ID for later continuation |
| `data.data[].audio_url` | Audio URL; also inspect clip state |

Do not apply v2's lowercase clip-state checks to the task layer or always treat `data.data` as a song array. Inspect actual types and fields against the intended task instead of relying only on the `action` label.

### Wait and prepare the download

Save this as `wait_for_suno_task.py`. It retrieves the existing task, handles failure states, and checks the completed song array. It never resubmits generation.

```python wait_for_suno_task.py
import json
import os
import sys
import time
from pathlib import Path
from urllib.parse import quote

import requests


def wait_for_music(task_id, budget=600):
    ready = Path("suno-newapi-ready.json")
    ready.unlink(missing_ok=True)
    if not isinstance(task_id, str) or not task_id.strip():
        raise ValueError("A nonempty task ID string is required")
    url = f"https://api.maxapi.ai/suno/fetch/{quote(task_id, safe='')}"
    headers = {"Authorization": f"Bearer {os.environ['MAXAPI_API_KEY']}"}
    deadline = time.monotonic() + budget
    raw = Path("suno-task-status.json")
    while time.monotonic() < deadline:
        raw.write_text("", encoding="utf-8")
        response = requests.get(url, headers=headers, timeout=(10, 30))
        raw.write_text(response.text, encoding="utf-8")
        response.raise_for_status()
        payload = response.json()
        if not isinstance(payload, dict) or payload.get("code") != "success":
            raise RuntimeError("Task query failed; inspect suno-task-status.json")
        task = payload.get("data")
        if not isinstance(task, dict) or task.get("task_id") != task_id:
            raise ValueError("Response task_id does not match the requested task")
        status = task.get("status")
        print(status, task.get("progress", ""))
        if status in {"FAIL", "FAILURE"}:
            raise RuntimeError(task.get("fail_reason") or "Music task failed")
        if status == "SUCCESS":
            songs = task.get("data")
            if not isinstance(songs, list) or not songs:
                raise ValueError("Expected a nonempty music result array")
            for song in songs:
                if not isinstance(song, dict) or not isinstance(song.get("id"), str) or not song["id"]:
                    raise ValueError("Invalid song object or clip ID")
                metadata = song.get("metadata") or {}
                if not isinstance(metadata, dict):
                    raise ValueError("Invalid song metadata")
                if metadata.get("error_type") or metadata.get("error_message"):
                    raise RuntimeError(metadata.get("error_message") or "Clip generation failed")
                if song.get("status") != "complete" or not song.get("audio_url"):
                    raise ValueError("Completed task contains an incomplete audio result")
            ready.write_text(json.dumps({
                "protocol": "newapi", "task_id": task_id, "clips": songs
            }, ensure_ascii=False, indent=2), encoding="utf-8")
            return songs
        remaining = deadline - time.monotonic()
        if remaining > 0:
            time.sleep(min(5, remaining))
    raise TimeoutError("Task is not complete; retain the ID and resume retrieval later")


if __name__ == "__main__":
    Path("suno-newapi-ready.json").unlink(missing_ok=True)
    if len(sys.argv) != 2:
        raise SystemExit("Usage: python3 wait_for_suno_task.py TASK_ID")
    songs = wait_for_music(sys.argv[1])
    print(f"Completed {len(songs)} songs; saved to suno-newapi-ready.json")
```

```bash Wait for the existing task
python3 -m pip install requests
python3 wait_for_suno_task.py "$TASK_ID"
```

Each received response is saved verbatim to `suno-task-status.json` before status or JSON checks. The returned `task_id` must match this request before `suno-newapi-ready.json` is created. Network, HTTP, or JSON errors leave no ready result. The download script checks the ready task against the current submission in `suno-task.json` again:

```bash Download the current NewAPI task
python3 save_suno_audio.py newapi
```

The `*-ready.json` files are local validation records, not API response envelopes. v2 uses its separate `suno-v2-ready.json`; the protocols do not share a result file.

The 5-second interval and 600-second budget are example client policies; individual requests also have timeouts. HTTP or business errors stop the script. Resolve the error and retrieve the same task ID again.

## Extend an existing song

Choose a song clip ID from completed results and select a position in seconds. Do not use a NewAPI task ID or v2 generation-level ID as `continue_clip_id`.

### v2 continuation

Keep `mv`, new lyrics in `prompt`, and style fields in the [v2 generation request](/en/api-reference/suno/v2-generate), then add:

```json Additional fields, merge into the full generation request
{"continue_clip_id": "YOUR_SOURCE_CLIP_ID", "continue_at": 30}
```

Submit to `/suno/v2/generate` again. The returned new `clips[].id` values identify the clips to retrieve for this continuation.

### NewAPI-compatible continuation

This example uses the compatible `task: "extend"` convention. Set the source song clip ID, continuation time, and enabled model first:

```bash Submit a new continuation task
set -euo pipefail
: > suno-task.json
: > suno-newapi-ready.json
: "${MAXAPI_SUNO_MODEL:?Set an enabled mv value}"
: "${MAXAPI_SUNO_CLIP_ID:?Set an existing song clip ID}"
: "${MAXAPI_CONTINUE_AT:?Set the continuation position in seconds}"
jq -n \
  --arg mv "$MAXAPI_SUNO_MODEL" \
  --arg clip "$MAXAPI_SUNO_CLIP_ID" \
  --argjson at "$MAXAPI_CONTINUE_AT" '{
    mv: $mv,
    task: "extend",
    prompt: "[Verse]\nFollow the light along the way\nSing a new story for the day",
    tags: "acoustic pop, warm vocals",
    title: "A new road: continuation",
    continue_clip_id: $clip,
    continue_at: $at
  }' | curl --fail-with-body https://api.maxapi.ai/suno/submit/music \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data-binary @- \
  --output suno-task.json
```

Some compatible flows also require the original `task_id`, according to channel requirements; it does not replace the source clip ID. After successful submission, run “Extract the task ID” again, then use `wait_for_suno_task.py` to retrieve the new task.

A continuation may contain only the added segment, not an already combined full song. Uploaded-audio model suffixes and concatenation belong to other protocol workflows and should not be applied to every model version.

## Troubleshoot music tasks

| Symptom | What to check |
| --- | --- |
| Submission succeeds but `feed` returns no song | Use `clips[].id` and separate multiple IDs with commas |
| Outer status is complete but audio URLs are empty | Inspect every clip; the wrapper status does not replace clip status |
| One song is complete and another is pending | Store states separately and decide whether your app delivers each song or the whole batch |
| `audio_url` exists but audio is incomplete | Wait for that clip's `status` to become `complete` |
| Continuation cannot find the original song | Use a song clip ID accessible through the current channel |
| Successful NewAPI submission has no parsed task ID | Check whether `data` is a string or an object; do not always read `data.task_id` |
| NewAPI parser cannot find songs | Read `data.data[]`, not the v2 top-level `clips[]` |
| Downloaded content is not audio | Inspect HTTP status and media type, then query the current link; do not save a JSON error as MP3 |



See the [catalog](/en/api-reference/catalog) for upload and lyric operations, and [asynchronous tasks](/en/guides/async-tasks) for polling, persistence and duplicate-request handling.
