MaxAPI's Midjourney API uses asynchronous tasks: **submit a prompt → receive a task ID → query the completed result → choose an image action**. It does not use Chat Completions or require a chat `model` field in the request body.

## Choose your workflow

| What you want to do | API | Next step |
| --- | --- | --- |
| Generate images from text, with optional reference images | [Imagine](/en/api-reference/midjourney/imagine) | Query the task for images and buttons |
| Combine multiple images | [Blend](/en/api-reference/midjourney/blend) | Query the generated result |
| Generate prompts from an image | [Describe](/en/api-reference/midjourney/describe) | Read the descriptions, then choose a prompt to generate an image |
| Analyze and shorten a prompt | [Shorten](/en/api-reference/midjourney/shorten) | Read the analysis, then choose a prompt to generate |
| Select an image, vary it, reroll, zoom or pan | [Action](/en/api-reference/midjourney/action) | Query the next task or continue through Modal |
| Edit a prompt, redraw a region or confirm an interaction | [Modal](/en/api-reference/midjourney/modal) | Submit the additional input, then query the final task |

For complete image-input examples, see [Reference images, Blend and Describe](/en/media/midjourney/inputs). For U/V buttons, Remix and region editing, see [Follow-up actions](/en/media/midjourney/actions).

## Configure your environment

Get a key with Midjourney access from the [console](https://platform.maxapi.ai). The terminal examples below use Bash, `curl`, Python 3 and `jq`.

```bash
export MAXAPI_API_KEY="REPLACE_WITH_YOUR_MAXAPI_API_KEY"
export MAXAPI_MJ_BASE_URL="https://api.maxapi.ai/mj"
```

| Mode | Base URL |
| --- | --- |
| Fast | `https://api.maxapi.ai/mj` |
| Turbo | `https://api.maxapi.ai/mj-turbo/mj` |
| Relax | `https://api.maxapi.ai/mj-relax/mj` |

Choose a mode available to your account and use it consistently for submission, queries and follow-up actions. **Do not append `/v1` to these URLs.** Pricing, quotas and availability depend on your account configuration.

## 1. Submit an image task

This prompt creates a ceramic cup image for a product display. Set `botType` to `MID_JOURNEY`, or use `NIJI_JOURNEY` for Niji.

```bash
curl --fail-with-body "$MAXAPI_MJ_BASE_URL/submit/imagine" \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{
    "botType": "MID_JOURNEY",
    "prompt": "A handmade ceramic cup on a clean studio background, soft side lighting, product photography",
    "state": "product-photo-001"
  }' \
  --output mj-submit.json
```

A successful submission has this structure. `TASK_A` is an illustrative placeholder:

```json
{
  "code": 1,
  "description": "Submitted successfully",
  "result": "TASK_A"
}
```

`code: 1` means the task was accepted; `code: 22` means it was queued. Neither means the image is ready. Save the task ID in `result`. An HTTP `200` response alone does not establish business success.

After the command completes, extract your task ID. Python preserves JSON integer precision before converting the ID to a string:

```bash
TASK_ID="$(python3 - <<'PY'
import json
from pathlib import Path

result = json.loads(Path("mj-submit.json").read_text(encoding="utf-8"))
if result.get("code") not in (1, 22):
    raise SystemExit(result.get("description", "Submission was not accepted"))
task_id = result.get("result")
if isinstance(task_id, bool) or not isinstance(task_id, (str, int)) or str(task_id) == "":
    raise SystemExit("No valid task ID in result")
print(str(task_id))
PY
)"
: "${TASK_ID:?Check the business result in mj-submit.json first}"
export TASK_ID
```

## 2. Query the task until it completes

```bash
TASK_ID_ESCAPED="$(python3 -c 'import os, urllib.parse; print(urllib.parse.quote(os.environ["TASK_ID"], safe=""))')"
curl --fail-with-body "$MAXAPI_MJ_BASE_URL/task/$TASK_ID_ESCAPED/fetch" \
  -H "Authorization: Bearer $MAXAPI_API_KEY" \
  --output mj-task.json

jq '{id, status, progress, imageUrl, failReason}' mj-task.json
```

While the task is pending, you may see `NOT_START`, `SUBMITTED` or `IN_PROGRESS`. Query **the same task** again later instead of resubmitting Imagine. [Task status and callbacks](/en/media/midjourney/tasks) includes a runnable polling script.

Example completed task:

```json
{
  "id": "TASK_A",
  "action": "IMAGINE",
  "status": "SUCCESS",
  "progress": "100%",
  "imageUrl": "https://example.com/generated-grid.png",
  "buttons": [
    {"label": "U1", "customId": "COPY_THE_ACTUAL_CUSTOM_ID_FROM_THIS_TASK"}
  ]
}
```

Check for `status: "SUCCESS"` before reading the finished `imageUrl`. A preview URL can appear during generation, so a nonempty URL alone does not prove completion. Read `failReason` when the status is `FAILURE`; `CANCEL` means the task was cancelled.

## 3. Read the image and its buttons

A typical image result may contain a four-image grid. `buttons` lists the actions available for this particular result: `label` is the name you display, while `customId` identifies the action you submit to the API.

```bash
jq -r '.buttons[]? | [.label, .emoji, .customId] | @tsv' mj-task.json
```

For example, to select the first image, find `U1` in this task's returned buttons. Submit its complete `customId` together with the task's `id` to Action. Do not send the literal string `"U1"` as `customId` or copy an action identifier from another task.

| Identifier | Where to get it | Where to use it |
| --- | --- | --- |
| Original task ID | Imagine's `result`, or the queried task's `id` | Action's `taskId` |
| Action identifier | This task's `buttons[].customId` | Action's `customId` |
| Follow-up task ID | Action's or Modal's `result` | Subsequent task queries; stop querying the original task for this result |

## Common integration mistakes

| Symptom | What to do |
| --- | --- |
| A task ID is returned, but no image | Submission and queries are separate requests. Continue querying until the task succeeds. |
| The original image still appears after an upscale action | Save the task ID returned by Action and query that follow-up task. |
| Action returns `code: 21` with an input-required description, or the task status is `MODAL` | Follow the [Modal workflow](/en/media/midjourney/actions) to provide the required input. |
| The task cannot be found | Check that the key, complete ID and mode prefix match the submission. |
| An ID stops matching after being stored in JavaScript | Keep IDs as strings instead of converting them to `Number`. Use lossless JSON parsing for oversized numeric IDs. |

`state` is your own business reference, such as an order or generation-record identifier. It is not a task ID and cannot replace `taskId`.
